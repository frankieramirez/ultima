# Readiness ledger

Decisions about agent readiness that this project owns: each correction promoted into enforcement, with its evidence, the route chosen and the guidance it replaced. Execution results stay in attributable run reports and pull requests; this file records the decision and points at them. The record fields come from [Mana's agent correction contract](https://github.com/frankieramirez/mana/blob/main/docs/plans/agent-correction-contract.md#correction-record-and-acceptance). Append a record for a new promotion or a material change, never for a timestamp refresh.

| Sources and observations | [Agent correction contract, Ultima pilot](https://github.com/frankieramirez/mana/blob/main/docs/plans/agent-correction-contract.md#ultima-reject-fixed-palette-literals-in-component-style-assertions): a documented policy ([What a build ticket proves](../spec/ultima.md#what-a-build-ticket-proves), "no test asserts a color value") with no rule in the analysis catalogue. Observation type: policy inspection. Independent incidents: none recorded. Repeat count: none. The refreshed inventory found no violation in the scope. |
| Intended outcome and consequence | A component behavior test never pins a generated palette value. A pinned value turns each palette regeneration into test edits, and it keeps passing when a part stops reading its token, as long as the old value stays the same. |
| Current enforcement and route | Deterministic check: [`ULT-TEST-001`](../spec/agent-infrastructure.md#component-color-assertions) in `packages/analysis/src/rules/assertions.ts`, blocking in `pnpm check:architecture`. A type or interface cannot express the restriction, because a color comparison is legal TypeScript and legitimate in other forms. A repository-wide regex would reject unrelated hex text and the token tests whose contract is an exact emitted value. |
| Bad case and valid alternative | Fixtures under `packages/analysis/fixtures/assertions/`, run by `packages/analysis/src/__tests__/assertions.test.ts`. Rejected: an `rgb()`, hex or `oklch()` literal, a local alias, an object member, a template literal, a constant exported by a sibling test file, and a paint property destructured from a computed style. Accepted: before/after comparisons, the installed token read through a probe, transparent paint, a `url(#id)` paint reference and unrelated hex text. A literal the test installs as an override passes only when the assertion compares computed values, such as the part's paint before and after the override; asserting the override literal itself is still rejected, as the policy requires. Incomplete analysis: a parameter, a `let` binding holding the expected value or the computed style, an undivided destructuring pattern and an unresolvable computed key. Limits: function results and values imported from outside the component test directories count as computed; custom property values are outside the rule. |
| Palette mutation | Executed in a Vitest browser run of Alert's proof (see the delivering pull request for the output). The run used the preinstalled substitute Chromium headless shell r1194 through a temporary, uncommitted `executablePath` override, because Playwright's pinned r1243 could not be downloaded in that environment; it is not a run on the pinned browser. With mithril `light1` changed, the token-derived assertion kept passing and a pinned `rgb(253, 253, 253)` copy failed. With Alert's neutral background then disconnected to the old literal, the token-derived assertion failed and the pinned copy passed. The static verdicts do not change with the palette, which `assertions.test.ts` checks. |
