# What Base UI 1.8 ships for the six remaining v0.2 lines

## Findings

Checked against the installed `@base-ui/react@1.8.0` (pnpm store path below; `package.json` says `1.8.0`, released Sep 4, 2026). The package's `exports` map, its `index.d.mts`, and the `docs/` markdown it ships are the source for everything here. The six unchecked v0.2 lines are Command; Calendar and Date Picker; Data Table; Button Group / Input Group / Input OTP / Native Select; Aspect Ratio / Resizable / Carousel; and the Chart / Item / Kbd / Typography recipes. Data Table's engine is already decided (TanStack recipe, ULT-72/ADR 0007) and needs no new primitive, so it is not re-covered here.

**Command — yes, via `Autocomplete`, and the docs ship the exact recipe.** `@base-ui/react/autocomplete` exports `Autocomplete` with 21 parts plus two hooks. Its own parts: `Root`, `Value`, `Trigger`, `InputGroup`, `Item`, `Separator`. Re-exported verbatim from Combobox: `Input`, `Icon`, `Clear`, `List`, `Status`, `Portal`, `Backdrop`, `Positioner`, `Popup`, `Arrow`, `Group`, `GroupLabel`, `Row`, `Collection`, `Empty`. Hooks: `useFilter`, `useFilteredItems`. No `Label`, `Chips`, `Chip`, `ChipRemove`, or `ItemIndicator` — the input holds free text, not a selection. `Root` renders no element. The usage guidelines say plainly "Can be used for filterable command pickers," and the shipped "Command palette" example composes `Dialog` + `Autocomplete.Root open inline items autoHighlight="always" keepHighlight` + `ScrollArea`, activating commands through `Item`'s `onClick` (Enter on the highlighted item fires it). `Root`'s `inline` prop renders the list without the component's own popup, so a command-dialog needs `Autocomplete.Root inline open` inside `Dialog.Popup`. ARIA contract (shared machinery with Combobox, verified in `combobox/root/AriaCombobox.mjs` and part sources): the input gets `role="combobox"`, `aria-expanded`, `aria-haspopup` (`"listbox"`/`"grid"`, or `"dialog"` when the input is inside the popup), `aria-controls`, `aria-autocomplete` from the `mode` prop (`'list' | 'both' | 'inline' | 'none'`; `"none"` when readonly), `aria-activedescendant` for virtual focus, plus `autoComplete="off"`, `spellCheck="false"`, `autoCorrect="off"`, `autoCapitalize="none"`. `List` is `role="listbox"` (`"grid"` in grid mode); `Item` is `role="option"` (`"gridcell"` inside `Row`); `Group` is `role="group"` (`"rowgroup"` in grid mode since 1.8.0); `GroupLabel` is `aria-hidden` (1.8.0); `Status` and `Empty` are `role="status"` live regions; `Popup` is `role="presentation"` or `role="dialog"` when the input is inside it; `InputGroup` is `role="group"`; `Backdrop` is `role="presentation"`. Keyboard: ArrowUp/ArrowDown navigate with `loopFocus` default `true` and the input always in the loop per the APG, Enter activates the highlighted item, Escape closes (`reason: 'escape-key'`), grid mode adds two-dimensional arrows. Data attributes (docs tables): `Trigger`/`Input`/`Group`/`InputGroup` carry `data-popup-open`, `data-popup-side`, `data-list-empty`, `data-pressed`, `data-disabled`, `data-readonly`, `data-required`, `data-valid`, `data-invalid`, `data-dirty`, `data-touched`, `data-filled`, `data-focused`; `Item` carries only `data-highlighted` and `data-disabled` (no `data-selected` — there is no selection state); `Popup`/`Positioner` carry `data-open`, `data-closed`, `data-anchor-hidden`, `data-align`, `data-empty`, `data-side` plus `data-starting-style`/`data-ending-style` on `Popup`; `Clear` adds `data-visible`; `Arrow` adds `data-uncentered`. The accessible name is on the consumer: `aria-label`, `<label>`, or `Field.Label` — there is no `Autocomplete.Label`. Status: stable, no deprecation; present since the 1.0.0 beta line, and the command-palette props (`inline`, `autoHighlight`, `keepHighlight`) are all current API. `Combobox` (`@base-ui/react/combobox`, 26 parts + `createItems`) is the sibling for actual value selection — not what Command wants.

**Calendar and Date Picker — no Base UI path.** There is no `calendar`, `date-field`, `date-picker`, or `date-*` directory, subpath, export, or docs page in 1.8.0, and base-ui.com's component index lists none. The only date groundwork in the package is dead internals: `./internals/temporal` (a `TemporalAdapter` interface over a `TemporalSupportedObject`/`TemporalRangeValue` value model, with format tokens like `yearPadded`/`month3Letters`) plus `./internals/temporal-adapter-date-fns` and `./internals/temporal-adapter-luxon` adapter classes. All three are in the `exports` map, but nothing in the package imports them — no component consumes the adapter in 1.8.0. So a Calendar or Date Picker today is either a plain component over a native grid/table, or an engine recipe under ADR 0007 with a headless date engine as the consumer's dependency. The temporal internals being on the roadmap says nothing usable ships yet.

**Input OTP — yes, `OTPField`.** `@base-ui/react/otp-field` exports `OTPField` with three parts: `Root` (renders `<div>`), `Input` (one `<input>` per character slot, repeated `length` times), and `Separator` (the standalone `Separator` re-exported). `Root` props: required `length`, `value`/`defaultValue`/`onValueChange`, `validationType` (`'numeric' | 'alpha' | 'alphanumeric' | 'none'`, default `'numeric'`), `mask`, `autoComplete` default `'one-time-code'`, `inputMode`, `autoSubmit` (submits the owning form when complete), `onValueComplete`, `onValueInvalid`, `normalizeValue`, `name`, `form`, `disabled`, `readOnly`, `required`, `id`. A hidden validation input carries the value for form submission. Keyboard (from `OTPFieldInput.mjs`): ArrowLeft/ArrowRight move between slots RTL-aware, Home/ArrowUp jump to the first slot, End/ArrowDown to the last, Backspace/Delete clear and step back, paste distributes across slots. ARIA: labeling is consumer-wired — a `<label htmlFor>`/`Field.Label` names the first slot and the docs pattern is `aria-label="Character N of M"` on slots 2..N; `aria-describedby` for supporting text; Field integration gives the seven shared validity attributes. Data attributes on both `Root` and `Input`: `data-disabled`, `data-readonly`, `data-required`, `data-valid`, `data-invalid`, `data-dirty`, `data-touched`, `data-complete`, `data-filled` (per-slot on `Input`), `data-focused`. `Separator` takes `orientation`, no data attributes. Status: stable — added as preview `OTPFieldPreview` in 1.4.0, renamed to `OTPField` and unmarked preview in 1.6.0 (the only other preview marker the library ever used was Drawer's).

**Native Select — no Base UI path; nothing needed beyond the platform `<select>`.** `@base-ui/react/select` is a fully custom listbox: `Trigger` renders a `<button>` with `role="combobox"`, `aria-expanded`, `aria-haspopup="listbox"`, `aria-controls`, `aria-labelledby`; `List` is `role="listbox"`; `Item` is `role="option"` with `aria-selected`; form value goes through hidden `<input>` elements, never a real `<select>` (18 parts total). It is the wrong primitive for a native-styled select — Ultima already ships it as `select.tsx`. A Native Select is the same shape as Badge or Table: a styled platform element, with `Field` supplying label/description/error wiring (any control inside `Field.Root` works; `Field.Control render={<select/>}` exists but is unnecessary). The only non-platform piece shadcn's version adds is a decorative chevron, which is paint, not behavior. Same line, briefly: **Button Group** and **Input Group** also have no dedicated primitive. The grouping primitives that exist are `Fieldset` (`Root` renders `<fieldset>`, `Legend` renders `<div>`), `Toolbar` (`role="toolbar"`, roving tabindex), `ToggleGroup` (`role="group"`), and the `InputGroup` parts that live only inside Combobox/Autocomplete (`role="group"` wrapper). None is a button/input group; both names point at styled-element components.

**Aspect Ratio — no Base UI path.** No part, hook, or subpath. A single element with the CSS `aspect-ratio` property is the whole component; `useRender` on the root is the established plain-component pattern.

**Resizable — no Base UI path.** No splitter/handle primitive, no panel-group behavior. Under ADR 0007 this is engine territory (a headless panel engine as the consumer's dependency) or out of scope; nothing in the package provides the pointer-drag sizing contract.

**Carousel — no Base UI path.** No carousel primitive or docs page. Engine recipe territory (embla-class engines), same as Resizable.

**Chart / Item / Kbd / Typography recipes — no Base UI path, by design.** No chart, item, kbd, or typography primitive exists; base-ui.com's index lists none. Chart is the clearest ADR 0007 case after Data Table: it needs a headless engine the consumer installs. Item, Kbd, and Typography are styled-element recipes — `<li>`/flex-row markup, `<kbd>`, and prose type — with no roles, ARIA state, keyboard handling, or focus management to delegate, so nothing for ADR 0002's library to supply.

**Deprecation status across all of the above:** nothing here is deprecated or `unstable-`. The package's only `unstable-` export remains `./unstable-use-media-query`. The two preview-marked components in the library's history, `Drawer` and `OTPField`, are both stable today.
