# What do the Data Table recipe's filtering and pagination examples need under `@tanstack/react-table@9.2.4`, and which catalogue component owns each new control?

## Findings

Both examples keep the shape the two shipped examples established (`apps/docs/src/demos/table/data-table-sorting.tsx`, `data-table-row-selection.tsx`): one module-scope `tableFeatures()` registration per example, `useTable({ features, columns, data })`, `createColumnHelper<typeof features, Row>()`, `helper.columns([...])`, render with `table.getHeaderGroups()` / `table.getRowModel().rows` / `<table.FlexRender header|cell>`, and a pre-mounted clip-hidden `role="status" aria-atomic="true"` announcer owned by the demo. The v9 hook is `useTable`, not `useReactTable` — the v8 name survives only as deprecated `useLegacyTable`. Filtering and pagination are independent feature sets, so they can ship as two independent examples; they can also merge into one `tableFeatures()` call later, because every feature owns its own state slice and the row-model pipeline is fixed.

**Filtering example.** Feature registration is `columnFilteringFeature` plus `filteredRowModel: createFilteredRowModel()` plus a `filterFns` map of only the built-ins the columns name (`filterFn_includesString`, `filterFn_arrIncludesSome`, etc.; `filterFns` full-registry still works but bundles everything). Faceting adds `columnFacetingFeature` with three factory slots — `facetedRowModel: createFacetedRowModel()`, `facetedUniqueValues: createFacetedUniqueValues()`, and `facetedMinMaxValues: createFacetedMinMaxValues()` only if a numeric range is shown; each getter needs its matching factory slot or the API does not exist. A global text filter additionally needs `globalFilteringFeature`, which has a hard prerequisite on `columnFilteringFeature` (`FeatureSlotPrereqs`) — registering it alone is the documented critical mistake.

- State slices: `table.state.columnFilters` (`Array<{ id, value }>`), `table.state.globalFilter` (`any`).
- Column APIs: `column.setFilterValue(updater)` (updaters receive the previous value; values failing the fn's `autoRemove` are dropped from state), `column.getFilterValue()`, `column.getIsFiltered()`, `column.getCanFilter()` (false on display columns like the selection column), `column.getFacetedUniqueValues()` → `Map<value, count>`, `column.getFacetedMinMaxValues()` → `[number, number] | undefined`. A column's facet deliberately excludes that column's own filter while applying the others, so read missing entries as `?? 0`.
- Table APIs: `table.setGlobalFilter(updater)`, `table.resetGlobalFilter()`, `table.resetColumnFilters()`, `table.setColumnFilters()`, `table.getFilteredRowModel()`, `table.getPreFilteredRowModel()`, `table.getColumn(id)`.
- Column-def options: `filterFn: 'includesString' | 'arrIncludesSome' | 'equals' | ...` (registered names, or `'auto'`, or a function), `enableColumnFilter`, `enableGlobalFilter`. Table options: `globalFilterFn`, `getColumnCanGlobalFilter` (default eligibility scans the first core row for string/number values), `enableFilters`, `manualFiltering`, `filterFromLeafRows`, `maxLeafRowFilterDepth`.
- Controlled state is optional: `state: { columnFilters }` + `onColumnFiltersChange`, `state: { globalFilter }` + `onGlobalFilterChange`; callbacks receive value-or-updater, so resolve with `functionalUpdate`. The shipped demos run uncontrolled (the engine's store drives `table.state` re-renders) and these can too. `initialState.columnFilters` / `initialState.globalFilter` set starting values only.

**Pagination example.** Feature registration is `rowPaginationFeature` plus `paginatedRowModel: createPaginatedRowModel()`.

- State slice: `table.state.pagination` = `{ pageIndex, pageSize }` (0-based index; `pageSize: Infinity` puts all rows on one page). `initialState: { pagination: { pageIndex: 0, pageSize: N } }` sets the start; default pageSize is 10.
- Table APIs: `setPageIndex`, `nextPage`, `previousPage`, `firstPage`, `lastPage`, `setPageSize`, `setPagination`, `getPageCount`, `getRowCount`, `getPageOptions`, `getCanNextPage`, `getCanPreviousPage`, `getCanLastPage`, `resetPageIndex`, `resetPageSize`, `resetPagination`, `getPaginatedRowModel()`, `getPrePaginatedRowModel()`. Options: `autoResetPageIndex` (defaults on for client pagination — a filter or data change snaps back to page 0, which is the desired composed behavior), `manualPagination`, `rowCount`, `pageCount`, `onPaginationChange`.
- `useTable` accepts a second selector argument, e.g. `(state) => ({ pagination: state.pagination })`, which narrows re-renders; `table.Subscribe`/`table.atoms.<slice>` are the per-subtree equivalents if a composed example wants targeted subscriptions.

**Composition.** The built-in row-model pipeline is fixed: core → filtering → grouping → sorting → expanding → pagination (`coreRowModelsFeature.utils`). `table.getRowModel()` is the end of that pipeline, so the render loop the shipped demos already use stays correct for both new examples and for any merged feature set — `getPaginatedRowModel()` slices the sorted model, which reads the filtered model. An unregistered stage returns its pre-model, so nothing changes when only one feature is present. Row selection keys state by row id and is unaffected. The one interaction that needs nothing extra is filter-change-resets-page: `autoResetPageIndex` covers it by default. The announcement obligation from the sorting/selection examples applies again: a page change and a filter change both move rows silently, so each example's `role="status"` region announces the new position ("Page 2 of 4") or result count — same pattern, new text.

**Control ownership.** Every interactive surface comes from the catalogue, per the settled rule that a recipe's controls are Ultima's even though its engine is not:

| Surface | Owner | Wiring |
| --- | --- | --- |
| Faceted column filter (discrete values with counts) | `DropdownMenu` — `Root` > `Trigger render={<Button/>}` > `Portal` > `Positioner` > `Popup` > `CheckboxItem` + `CheckboxItemIndicator`; `Button` owns the trigger | Items from `table.getColumn('x').getFacetedUniqueValues()`; `checked` from `column.getFilterValue()` array membership; `onCheckedChange` → `column.setFilterValue` with `filterFn: 'arrIncludesSome'` |
| Filter trigger glyph/label | `Button` (via `DropdownMenu.Trigger`'s `render` slot) | — |
| Page navigation | `Pagination` — `Root`/`List`/`Item`/`Previous`/`Page`/`Next`/`Ellipsis` plus pure `Pagination.getPages({ page, count })` | `page = state.pagination.pageIndex + 1`, `count = table.getPageCount()`; `onClick` → `table.setPageIndex(entry.page - 1)`, `table.previousPage()`, `table.nextPage()`; `disabled={!table.getCanPreviousPage()}` etc.; `current={entry.page === page}` |
| Pagination element shape | `Pagination.Previous`/`Page`/`Next` with `render={<button type="button" />}` | The catalogue parts default to `<a>` for link pagination; the button render for a state-driven table is already the shipped pattern in `apps/docs/src/demos/pagination/window.tsx`. `disabled` emits `aria-disabled` + `data-disabled` and swallows activation — never the native attribute. |
| Global search box, if shown | `Input` (named by `aria-label` or an associated `<label>`; `Field` is optional) | `onChange`/`onValueChange` → `table.setGlobalFilter` |
| Rows-per-page chooser, if shown | `Select` | `onValueChange` → `table.setPageSize(Number(value))` |

Two facts for the decision ticket. First, the spec's checklist entry already records the recipe's component dependencies as `table`, `button`, `checkbox`, `dropdown-menu`, and `pagination` (`docs/spec/ultima.md`, the unchecked Data Table line) — that set covers a Dropdown Menu faceted filter and Pagination navigation exactly, but not `input` or `select`. A global-search `Input` or a page-size `Select` is supported by the engine and by the catalogue, yet each one extends the settled dependency list and is a decision for #282, not a given. Second, the catalogue `Pagination` ships only `Previous`/`Next` end controls — there are no First/Last parts — so `table.firstPage()`/`table.lastPage()` have no matching surface and the page-number items carry that navigation.
