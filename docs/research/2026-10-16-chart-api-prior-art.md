# How do comparable design systems shape their chart APIs: one Chart wrapper, per-type components, or a recipe?

## Findings

**Two shapes exist, and the copy-source one is the thin wrapper.** shadcn/ui ships one file, `chart.tsx`, that wraps Recharts' own composition API (`ChartContainer` plus a styled tooltip and legend) and carries every chart type as a copyable example block: 70 of them. Tremor, Mantine and MUI X ship per-type components (`BarChart`, `LineChart`, ...) with fixed props over an engine they hide. MUI X also exposes the composition layer underneath. TanStack Charts is itself one `<Chart definition>` over composed marks and has no per-type components. Its docs show no design-system wrapper. The three systems already built on it each take a different shape: a token bridge with no wrapper, one wrapper plus a few pre-wired kinds, and about forty per-type components. No library ships a data table except Aperture. TanStack's docs tell the application to build one.

Everything below was read from the package source at the versions named, from the registry item shadcn serves, or from the vendor's docs page. Install costs come from a scratch `npm install --ignore-scripts` with `react@19.2.0` and `react-dom@19.2.0`. They count packages and `node_modules` megabytes beyond React, React DOM and scheduler.

### shadcn/ui charts (Recharts 3)

- **Shape: one wrapper plus the engine's own marks.** The registry item `chart` (`registry:ui`) is a single file exporting `ChartContainer`, `ChartTooltip`, `ChartTooltipContent`, `ChartLegend`, `ChartLegendContent`, and `ChartStyle`. `ChartTooltip` and `ChartLegend` are bare re-exports of `RechartsPrimitive.Tooltip` and `.Legend`. Only the `*Content` parts render shadcn markup. `ChartContainer` is a `div[data-chart]` with a context provider and Recharts' `ResponsiveContainer`. Its Tailwind classes repaint Recharts' default `#ccc` and `#fff` strokes to `border` and `muted`. The consumer writes `<BarChart>`, `<Bar>` and `<XAxis>` from `recharts` directly inside it. The docs state the policy: "We do not wrap Recharts." Each chart type is a separate `registry:block` (`chart-bar-default` and so on). Each block depends on `card` and `chart` and holds its data, its `chartConfig`, and the Recharts tree.
- **Series colors: `ChartConfig` → scoped CSS variables.** `ChartConfig` maps a series key to `{ label, icon, color }` or `{ label, icon, theme: { light, dark } }`. `ChartStyle` injects a `<style>` that sets `--color-<key>` on `[data-chart=<id>]`, and the marks paint with `fill="var(--color-desktop)"`. The theme supplies `--chart-1` through `--chart-5`, with different oklch values in light and dark (`theme-neutral.json` `cssVars`). Blocks use `color: "var(--chart-1)"`.
- **Dark and light:** with `color: var(--chart-N)`, the mode flip comes from the theme's own `.dark` override of `--chart-N`. With `theme: { light, dark }`, `ChartStyle` writes two rules, and its selector map is hard-coded: `const THEMES = { light: "", dark: ".dark" }`. A host that switches with `[data-theme]` or a media query gets only the light value from that path.
- **Accessibility:** the docs tell readers to add `accessibilityLayer` because it "adds keyboard access and screen reader support", and every block does. In Recharts 3 the prop already defaults to `true`. When it is on, the SVG surface gets `role="application"` and `tabIndex=0`, ArrowLeft and ArrowRight move the active tooltip index, and Enter toggles it. Recharts' `DefaultTooltipContent` adds `role="status" aria-live="assertive"`. shadcn's `ChartTooltipContent` replaces that component, drops the `accessibilityLayer` prop from its own props type, and renders a plain `div`, so a shadcn chart loses the live region. There is no data-table fallback.
- **Install:** registry `dependencies` are `cn`, `recharts@3.8.0`, and `lucide-react`. `chart.tsx` imports no lucide, and the registry dependency is `card`. `recharts@3.8.0` alone is 40 packages and about 41 MB, including `@reduxjs/toolkit`, `react-redux`, `immer`, `es-toolkit`, and `victory-vendor`. With `lucide-react` it is 42 packages and about 87 MB. The Base UI, Radix, and Aria bases carry the same file; the Base UI one differs only in `cn-chart*` class hooks.

### Tremor

- **Two products, both per-type.** `@tremor/react@3.18.7` (npm, last published 2025-01-13) and the copy-paste components at tremor.so (`tremorlabs/tremor`, last pushed 2025-10-10). The copy-paste set has one file per type: `AreaChart`, `BarChart`, `LineChart`, `ComboChart`, `DonutChart`, `SparkChart`, plus `BarList`, `CategoryBar`, `ProgressBar`, and `Tracker`. Each type has fixed props: `data`, `index`, `categories`, `colors`, `valueFormatter`, `type: "default" | "stacked" | "percent"`, `layout`, `showLegend`, `showTooltip`, `onValueChange`, `customTooltip`, and others. Recharts is hidden; `{...other}` goes to the outer `div`, not to the Recharts chart. Each file carries its own `Legend`, `LegendItem`, `ChartLegend` and `ChartTooltip`, so `BarChart.tsx` (885 lines), `AreaChart.tsx` (989) and `LineChart.tsx` (907) repeat the same chrome.
- **Series colors: a fixed Tailwind map, not variables.** `chartColors` maps names such as `blue` and `emerald` to literal classes like `fill-blue-500` and `stroke-blue-500`. `constructCategoryColors` assigns them by index. `colors` takes keys of that map only, so the colors are the same in both modes. The npm v3 package uses its own `tremor-*` Tailwind theme keys for chrome (`dark:fill-dark-tremor-content`).
- **Dark and light:** Tailwind `dark:` variants on chrome only (`dark:stroke-gray-800`, `dark:bg-gray-950`).
- **Accessibility:** the docs make no claim. The copy-paste files pin `recharts ^2.15.2`. Recharts 2 leaves `accessibilityLayer` undefined, which is off, and Tremor never passes it, so there is no chart keyboard layer. Only the legend slider is focusable and arrow-scrollable. There is no data table.
- **Install:** `npm i recharts` plus copied `chartUtils`/`chartColors.ts`, `useOnWindowResize.ts`, and `cx` (`clsx` and `tailwind-merge`). Measured: 42 packages, about 20 MB, for `recharts@2.15.4`, `clsx`, and `tailwind-merge`. The npm package adds `@headlessui/react`, `@floating-ui/react`, `react-day-picker`, and `date-fns`, and peers on React 18.

### MUI X Charts (v9.15.0)

- **Shape: both.** Per-type components (`BarChart`, `LineChart`, `PieChart`, `ScatterChart`, `RadarChart`, `Gauge`, and others) take `series` arrays. Under them sits a composition API: `ChartsContainer` is "the direct concatenation of `ChartsDataProvider` and `ChartsSurface`", with `BarPlot`, `LinePlot`, `ChartsXAxis`, `ChartsTooltip`, `ChartsLegend`, and `Focused*` parts as children. A per-type component is the self-contained form that assumes its series type. In composition the consumer sets `type` on each series.
- **Series colors:** a series `color`, a `colors` prop that takes an array or `(mode) => string[]`, or a per-point `colorGetter`. The default is `rainbowSurgePalette`, seven hex values with separate light and dark arrays (`colorPalettes/categorical/rainbowSurge`). `useChartSeries` defaults `colors` to that palette and resolves the callback with `theme`.
- **Dark and light:** `useChartsDataProviderProps` reads `theme.palette.mode` from the Material theme and passes it to the palette callback, so mode comes from MUI's ThemeProvider, not CSS.
- **Accessibility:** keyboard navigation is on by default (`disableKeyboardNavigation` opts out). Left and Right move within a series, Up and Down move between series, Home and End go to the ends, Ctrl+Home and Ctrl+End go to the global ends, and PageUp and PageDown go to the first or last series. The docs mark keyboard navigation as still under development. Screen readers get a proxy, `ChartsAccessibilityProxy`: two focusable `role="img"` divs, each labelled by hidden text, that swap on each move, plus a `role="status" aria-live="polite"` region. Descriptions are localizable `[type]Description` functions. The page targets WCAG 2.2 AA and respects `prefers-reduced-motion`. It describes no data-table fallback.
- **Install:** `@mui/x-charts` has 11 dependencies, among them `@mui/x-charts-vendor`, `@mui/x-internals`, `@base-ui/utils`, and `reselect`. `@mui/material` and `@mui/system` are required peers; Emotion is optional (`peerDependenciesMeta`). Measured with Material and Emotion: 115 packages, about 64 MB.

### Mantine Charts (v9.7.2)

- **Shape: per-type components over Recharts.** There are 22 listed (`AreaChart`, `BarChart`, `LineChart`, `CompositeChart`, `DonutChart`, `PieChart`, `RadarChart`, `ScatterChart`, `Sparkline`, `Heatmap`, `Treemap`, `SankeyChart`, ...). Props are `data`, `dataKey`, `series: [{ name, color, label, stackId }]`, `type: "stacked" | "percent" | "waterfall"`, `withLegend`, and `withTooltip`. Escape hatches pass Recharts props through: `barProps`, `xAxisProps`, `yAxisProps`, `barChartProps`, and `children`.
- **Series colors:** `getThemeColor` turns a theme key (`'violet.6'`) into `var(--mantine-color-violet-6)` and passes any other CSS color through, `var(...)` included. A series without a color falls back to `theme.primaryColor`, so there is no categorical palette.
- **Dark and light:** chart chrome reads `--chart-grid-color`, `--chart-text-color`, `--chart-cursor-color` and similar variables. `styles.css` defines them under `[data-mantine-color-scheme='light'|'dark']`. Series colors flip only if the consumer passes a variable defined with `light-dark()` or the scheme mixins, which is the docs' advice.
- **Accessibility:** the docs say "All @mantine/charts components include an accessibility layer that makes charts navigable with the keyboard". Each component defaults Recharts' `accessibilityLayer` to `true`, so Mantine gets Recharts' Tab, Arrow, and Enter behavior. There is no data table.
- **Install:** `@mantine/core`, `@mantine/hooks`, `@mantine/charts`, `recharts >=3.2.1` (a peer), and `@mantine/charts/styles.css`. Peers on React `^19.2.0`. Measured: 60 packages, about 69 MB.

### TanStack Charts (`@tanstack/charts@1.1.0`, 2026-10-09)

- **Shape: one Chart, composed marks, no per-type components.** `defineChart({ marks: [lineY(...), barY(...)], scales, color, tooltip, theme })` builds a framework-neutral definition. `import { Chart } from '@tanstack/charts/react'` renders it with `ariaLabel` (required), `height` or `aspectRatio`, and focus and select callbacks. Canvas and custom-renderer variants live at `/react/canvas` and `/react/core`. `@tanstack/react-charts@1.1.0` is now a re-export "compatibility package"; new apps use the subpath. The "Coming from Recharts" guide maps Recharts props onto one `defineChart()` value.
- **Recommended wrapper: none in the docs.** The only first-party design-system material is the catalog's "shadcn/ui Charts" collection: 70 shadcn examples plus the dashboard, ported. Each case (`benchmarks/conformance/cases/1xx-shadcn-*/example.tsx`) is a plain `defineChart` plus `RendererChart` inside card markup. There is no `ChartContainer` or `ChartConfig` analogue. shadcn tokens map in place: `shadcnColors = ['var(--chart-1, var(--ts-chart-1))', ...]` and `theme: { foreground: 'var(--muted-foreground, ...)', grid: 'var(--border)' }`. `@tanstack/react-charts-catalog@0.7.2` ships one server-renderable component per catalog case, pinned to 0.7.2: per example, not per type.
- **Series colors: CSS variables by default.** The default theme is `foreground`, `muted`, and `grid: currentColor`, `background: transparent`, and `palette: var(--ts-chart-1, #2563eb)` through `var(--ts-chart-6, #06b6d4)` (`dist/scene.js`). The tooltip reads `--ts-chart-tooltip-*`. A definition-level `theme` overrides any of these. The guide calls container-scoped `--ts-chart-N` "the lowest-cost path for application branding".
- **Dark and light:** chrome inherits `color`, so it follows the page. The fallback hexes are the same in both modes until a container sets `--ts-chart-N`. Canvas resolves `var()` and repaints on `data-theme`, `color-scheme`, and `forced-colors` changes.
- **Accessibility:** the SVG is `role="img" aria-roledescription="chart"` with `aria-label`, an optional `<desc>`, and `tabindex="0"`. The keyboard follows pixel order: arrows move between points, Home and End go to the ends, and Enter or Space toggles a sticky tooltip and calls `onSelect`. The built-in tooltip is a polite status region. Reduced motion is respected. The accessibility guide puts the heading, units, summary and "a table when exact values matter" in application HTML, and shows a linked chart-and-table pattern with app-owned `<table>`, `role="status"`, and a clear button.
- **Install:** one package with 13 `d3-*` modules and 5 `@types/d3-*` as hard dependencies, including `d3-geo`, `d3-sankey`, and `d3-force`, which a bar chart does not use. All 13 framework peers are optional. Measured: 43 packages, about 10 MB.
- **Adopters (npm search, 2026-10-16):**
  - `@bysages/charts@0.4.3` re-exports TanStack's `Chart` per framework unchanged. An import side effect injects CSS that points `--ts-chart-1..6` and `--ts-chart-tooltip-*` on `.ts-chart` at its own `--bs-color-*` tokens. It is a token bridge with no wrapper and no per-type components.
  - `basalt-ui@2.13.2` (`./charts`, Mantine-free) has one `CartesianChart` entry that owns margins, scales, grid, cursor, keyboard focus, legend and tooltip. The consumer returns marks from `@tanstack/charts/*` subpaths. Pre-wired kinds (`Lines`, `Bars`, `StackedArea`, `Donut`, `Heatmap`, `Sparkline`, ...) are "that same composition, pre-wired". Colors come from `--vx-*` tokens shared with its Mantine theme. Its peers are `@tanstack/charts@1.1.0` and `d3-scale@4.0.2`, exact and optional.
  - `@kevin-courbet/aperture@0.8.0` has about 40 per-type components (`BarChart`, `LineChart`, `SankeyChart`, `WaterfallChart`, ...) plus a `ChartWidget` compound and an `/tanstack` escape hatch. Its `--aperture-chart-1..8` series tokens switch under `[data-theme=dark]` and `forced-colors`. It is the only system here that ships an exact-value table (`exactValues`, `DataTableControl`), collapsed but kept in the accessibility tree.
  - `@lionad/cx-comps-tanstack-charts@0.1.0` is Vue only and peers on pre-1.0 `^0.18`.

### Patterns that matter for one Chart vs several in a copy-source registry

1. **In copy-source, the per-type knowledge lives in examples, not components.** shadcn keeps one small item and puts every chart type in an installable block that the consumer edits. The npm systems (Tremor, Mantine, MUI) need per-type props plus pass-throughs (`barProps`, `xAxisProps`, composition mode, `/tanstack`) because the consumer cannot edit the source. A copied file does not need those pass-throughs.
2. **Per-type copied files duplicate chrome.** Tremor's three main chart files each redefine the legend and tooltip, about 900 lines apiece. A per-type registry would repeat tooltip, legend and axis code in every item or factor it into a shared item, which brings back the one-wrapper shape.
3. **TanStack's native shape is already the one wrapper.** On TanStack, a "Chart" item maps directly onto the engine, as bysages and basalt show. A per-type layer is an extra API on top. basalt keeps both: one composable entry, and kinds built from it.
4. **The token bridge can be CSS alone on TanStack.** TanStack reads `--ts-chart-N`, `--ts-chart-tooltip-*`, and `currentColor`, so pointing those at `--ult-*` tokens in a container style is the whole bridge, as bysages does. shadcn needs `ChartStyle` and a runtime `<style>` only because Recharts takes paint as props. Its `.dark` selector map would also not match Ultima's media-query plus `[data-theme]` switching.
5. **Every surveyed system leaves out the data table but Aperture.** Keyboard focus is now common (Recharts 3, MUI, TanStack). An exact-values alternative is not: TanStack documents it as the application's job, and only Aperture ships one. Ultima's current recipe rule (SVG `aria-hidden`, `Table` beside it) is stricter than every library here except Aperture.

### Facts later tickets will need

1. TanStack Charts' React surface is `Chart` from `@tanstack/charts/react`, with `ariaLabel` required. `@tanstack/react-charts` is a compatibility re-export. There is no per-type component and no documented design-system wrapper.
2. TanStack's theme hooks are `--ts-chart-1`..`--ts-chart-6` (fallback hexes in `dist/scene.js`), `--ts-chart-tooltip-background`, `-color`, `-border`, `-border-radius`, `-shadow`, `-max-width`, `-padding`, and `-font`, plus `currentColor` for foreground, muted and grid. A definition `theme` object overrides them per chart.
3. Ultima has no categorical series tokens today. The current recipe paints with `--ult-color-accent`, `-border`, `-text-subtle`, and `-text-muted` (`apps/docs/src/demos/table/chart.tsx`). A multi-series chart needs new tokens that pass the contrast gate in both modes; shadcn ships 5, TanStack 6, MUI 7, and Aperture 8.
4. TanStack's SVG takes `role="img"` and a tab stop whenever `keyboard` is on. That conflicts with the current recipe's `aria-hidden` SVG, so the accessibility contract has to choose between them.
5. `@tanstack/charts` hard-depends on 13 d3 modules whether or not they are used. The current recipe's `d3-scale`, `d3-array`, and `d3-format` are already among them, but a consumer installs all 13.
6. Recharts 3 defaults `accessibilityLayer` to `true`. shadcn's advice to add the prop is redundant there, and its custom tooltip drops Recharts' live region.
