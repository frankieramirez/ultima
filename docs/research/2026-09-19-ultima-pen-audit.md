# What does ultima.pen design, and where do its landing page, rethemed docs pages, and studio screens match or diverge from the site and the settled theme-studio spec?

## Findings

`ultima.pen` holds 28 top-level frames in three numbered groups: `01 / DESIGN DIRECTIONS` (landing explorations, including the shipped home page), `02 / INTERNAL PAGES` (eight "Variant 02" rethemed docs pages), and `03 / THEME STUDIO` (ten studio/color-field screens, of which `umu8k` "Final design" is the latest iteration). The file defines 58 `$ult-*` canvas variables that mirror the real semantic tokens in `packages/tokens/dist/tokens.json` one-to-one — including `--ult-color-action-*` and `--ult-color-surface-overlay` — under a two-theme (dark/light) variable setup, so the designs paint with production token names throughout.

### (a) Landing page

`Q9N2n` "Ultima — Syntax landing" (1602×1550) is essentially the already-shipped home page, not a new design. Its enabled tree is: `header` (wordmark + Dark/Light/System segmented control), left `nav` (`::root` group: `--home`, `--install`, `--tokens`, `--palette`, `--rationale`; `@components` group: 18 items), then `Hero` (eyebrow "ULTIMA / UI FOR STYLEX", "Exceptional interfaces. Down to the variable.", "Start building" + "Explore components" actions, "Built with StyleX" hint), `Component playground` (`--playground` toolbar with Preview/Code toggle, a mock project interface with tabs, two metrics, a 12-bar activity chart, "All systems ready" status, publish button; plus a `Token inspector` panel showing `theme.stylex.ts` code and four theme swatches), `Why Ultima` (`--built-different` marker, three numbered principles), `Closing invitation`, `Footer`. Every text and section matches `apps/docs/src/routes/home.tsx`, `demos/home/playground.tsx`, `site-menu.tsx`, and `header.tsx` verbatim.

A disabled `main` child inside `Q9N2n` preserves a superseded layout (intro "The final spell for the interfaces you build.", a "Live" section with Button/Card+Stat/Code demos, an "Install" section, and a `--install/--tokens/--palette/--rationale/--components` link footer).

Tokens/primitives/components the landing implies that the catalogue lacks: **none.** The mode toggle is the existing `ToggleGroup` usage already in `header.tsx` (Dark/Light/System options, `header.tsx:32-36`); the nav is `Sidebar`; hero/closing buttons instance the reusable `Ultima Button / Solid` (`l2yJUo`) and `/ Outline` (`xSOGe`) components; tabs, stats, code block, and status text in the playground map to Tabs, Stat, Code, and text. The activity bar chart is twelve decorative rectangles — Chart is not in the catalogue, but the mock does not demand one. The token-inspector panel and theme swatches are page-layout composition over Code, not new primitives.

Adjacent direction frames: `JmKDl` "Variant 01 · Neutral" (rejected direction: minimal top nav, icon theme toggle, "A foundation for interfaces that feel like yours."), `oShfg` "Variant 02 · Component workshop" (alternative landing: workshop nav, editorial hero "Good interfaces start with", specimen workshop, installation workbench), `WAWs3` "Primary button color studies" (three accent directions — 01 Ember marked "My pick", 02 Mithril, 03 Mana), `n4ZINm` imported button primitives, and `I0iEE`/`bi8Au` scratch frames (a browser import of the same page and an empty frame).

### (b) Rethemed docs pages

Eight "Variant 02" frames retheme existing routes: `eBqqH` Install → `/install`, `qytHE` Tokens → `/tokens`, `FOlK8` Palette → `/palette`, `ouXuK` Rationale → `/rationale`, `kZdew` Button, `aAvMa` Badge, `DCKku` Card, `dJ1Fs` Table → `/components/$name` exemplars. No `/components` index or home retheme appears in this set; the remaining ~38 component pages presumably follow the same template.

Structural changes shared by all eight pages, relative to the current site:

- New "Workshop navigation" top bar: wordmark, plain links "Components / Tokens / Documentation", status "v0 / IN DEVELOPMENT", "GitHub ↗". It **drops** the current header's Dark/Light/System `ToggleGroup` and the `Sidebar.Trigger` (`apps/docs/src/header.tsx:38-68`).
- Sidebar groups relabeled `::root` → "FOUNDATIONS" and `@components` → "COMPONENTS"; item labels become plain words ("Home" not "--home"), though the frame names keep the `--home`/`@components` motif (`navigation.ts` is the current source of the motif).
- Breadcrumb becomes plain "DOCUMENTATION / X" or "COMPONENTS / X" instead of the current `::root { --active: "x"; }` mono motif (`document-layout.tsx:146`, `page.tsx:66`).
- The "On this page" right rail is retained (it already exists: `document-layout.tsx:152-156`).
- Every page gains a "Workshop footer" ("ULTIMA / THE FINAL SPELL FOR YOUR INTERFACES" + Documentation/GitHub/MIT license). Only home has a footer today; `document-layout.tsx` has none.

Per page: **Install** keeps `install.mdx`'s exact five sections (Commands, What the setup item installs, Steps you still do by hand, Tokens without StyleX, For an agent). **Tokens** keeps the current page's group sections (Color, Space, Text, Font, Radius, Shadow, Motion) plus Pairings (FOREGROUND/BACKGROUND/WCAG DARK/WCAG LIGHT/APCA DARK/APCA LIGHT table) and Overriding; token rows show paired dark+light swatches, as the current page already does. **Palette** keeps Scales (six named scales), Step convention, Contrast gate — matching `routes/palette.tsx`. **Rationale** keeps `rationale.mdx`'s four sections (StyleX, Base UI, Registry-first, Dark-first). The four **component pages** share one template: breadcrumb, title, lede, Install (`npx shadcn add @ultima/<name>` code block), per-demo "specimen" blocks (live preview + full source code + Copy), Props table (PROP/TYPE/DEFAULT/NOTES), Accessibility list, On this page — the same sections the MDX pages carry, with the specimen block as the rethemed demo pattern.

### (c) Studio screens vs `docs/spec/theme-studio.md`

Ten studio-related frames: `umu8k` "Final design" and `ioTca` "Final · Picker open" (latest iteration, light and dark preview states; `ioTca` adds the picker popup), `SJ3zj` "Theme Studio C / The workbench" (same layout, dark preview, scene dropdown instead of tabs), `HxKqB` "Theme Studio B / Application canvas" (earlier rail iteration), `iG9vz` "Theme Studio / Compare" (earlier iteration under docs chrome, showing compare mode), `uW4F5` "Overrides and validation", `NWu3E` "Export dialog", `RUDDo` "Invalid export confirmation", `Y1ClP1` "Mobile editor" (390 px), `eITqK` "Color Field / Custom picker exploration".

**"### Theme studio layout and live preview"** — confirmations: compact left rail beside a large preview in every desktop frame (`iG9vz` literally names it "Fixed dark editing rail"); dark/light/compare segmented control in the preview toolbar (all frames); compare renders two side-by-side panes each forced to one mode ("DARK / LIVE PREVIEW" | "LIGHT / LIVE PREVIEW" in `iG9vz`); the shuffle bar tops the rail with Shuffle, Broad/Subtle variation toggle, undo, redo, and fingerprint "a7c3f2"; locks and per-group shuffle sit on every group header; "Inspect tokens" is an opt-in toolbar toggle, and the `03 / INSPECT` specimen shows a per-mode resolved readout ("--ult-color-accent / #345C43 · Light · Derived"); the editor chrome stays dark while the preview shows light (`umu8k`) — the "fixed dark editor appearance" contract; the 390 px `Y1ClP1` converges to preview-on-top plus a "Bottom editor sheet" with drag handle, matching the sub-~840 px bottom-sheet rule.

Divergences under the same section:

- **Scenes.** The spec settles "a single scrolling column of scenes: typography, controls, surfaces, overlays, forced states, and motion," and `iG9vz` confirms it (each compare pane is a column labeled 01 TYPOGRAPHY through 06 MOTION, including "05 / FORCED STATES" — matching the prototype's `sceneHTML` order in `apps/docs/public/theme-studio-prototype.html:521-597`). The final design `umu8k`/`ioTca` instead shows a **tab strip** — "Workspace, Typography, Controls, Surfaces, Overlays, States, Motion" — displaying one scene at a time, **adds a "Workspace" application-mock scene** (the "Forma" workspace), **renames forced states to "States"**, and adds a **"Theme specimen strip"** below the preview (01/TYPE, 02/INTERACTION with Rest/Hover/Active buttons, 03/INSPECT). `SJ3zj` collapses scenes to a "Workspace ⌄" dropdown with no tab strip; `HxKqB` labels them "Overview/Type/Controls/…".
- **Bottom draft status bar.** The final design adds a persistent bar the layout contract does not specify: "Token contrast · View report ↗", "Editing both modes", "2 overrides · 2 locked groups", "Reset theme". "Editing both modes" confirms the shared-seeds/both-modes edit model, but "Reset theme" is a whole-draft reset the spec does not name (the controls contract settles per-group resets).
- **Studio chrome.** `iG9vz` still sits under docs chrome (site nav links + "THE WORKSHOP / 01" title block + Open draft/Share/Export). The final "Workbench header" drops docs navigation entirely in favor of product title + draft name "Untitled theme" + "Saved locally" + Open/Share/"Export theme ↗" — consistent with "application surface rather than docs page layout" but a structural change in how the studio is reached.
- **Mobile groups.** `Y1ClP1` replaces the stacked group accordion with a horizontal group selector ("Color    Type    Density    Shape    …"); the spec only settles the bottom-sheet convergence, so the selector pattern is new design ground.
- Compare "stacked when narrow" is not depicted (mobile shows a single preview).

**"### Theme controls and token relationships"** — confirmations: exactly six guided groups (Color, Typography, Density, Shape, Elevation, Motion — numbered 01–06 in `iG9vz`); color exposes six scale seeds mapped to roles (Mithril/Neutral, Rune/Accent, Mana/Action, Verdant/Success, Ember/Warning, Ruin/Danger — consistent with action+highlight sharing the mana scale); the selected scale edits a hex value plus Hue (°) and Saturation (%) sliders, matching the hue-0–359/saturation-factor contract; a "Token overrides · 2" disclosure per expanded group matches the expandable per-token overrides; collapsed groups show resolved values ("Geist / Plex Mono", "Cosy", "Default", "Subtle", "Default") and lock state ("Locked" in `iG9vz`); preset names match the spec (Cosy, Round, Subtle, Default).

Divergences:

- **The accent scale is named "Rune"** in every studio frame ("Rune / Accent", `uW4F5`, `HxKqB`, mobile). `CONTEXT.md` and the palette name it **arcane** — either a rename proposal or design fiction; ticket #234 should decide.
- **The seed color field carries a "HEX" format selector and opens a multi-format picker** — the contract is "exact color overrides accept opaque sRGB values only" (see the Color Field divergence below).

**"### Shuffle, manual overrides, and validation"** — confirmations: two-level shuffle (per-group icons + global "Shuffle theme"); Broad/Subtle variation toggle; group-level locks; undo/redo icons; the exhaustion notice in `uW4F5` — "No passing palette found. Your draft is unchanged. 50 attempts · Review the failing pairings and your Color lock" — matches the 50-attempt bounded search including lock reporting; the validation panel reports per mode ("Dark 48/49 pass, Light 49/49 pass", "97 / 98 pass across dark and light" — 98 = 49 pairs × 2 modes, consistent with the 49-pair manifest); a failing-pairing card shows mode, tokens, threshold, and "Edit ↗"; the offending token row carries the error inline ("! Dark: text-muted on surface fails 4.5:1"); copy says "Token contrast" and "Checks the declared token pairings against WCAG 2.2 AA. Test your components in context too." — matching the "token contrast rather than accessible theme" wording contract; the mode-linked token row matches the composition contract exactly: "Derived"/"Overridden · Linked" states with one shared input, "Overridden · Unlinked" splitting into separate Dark and Light inputs, and relink help "Link modes to use the dark value for both" (dark-first).

**"### Theme export, installation, and recovery"** — confirmations: the header carries draft name, autosave state ("Saved locally" / "a7c3f2 · Saved on this device"), Open (draft upload), Share, and Export; `NWu3E` is a dialog with fingerprint + "Both modes included · 98 / 98 token pairings pass", tabs "Install in your app" / "Download files", a three-step install flow (download `ultima-theme.registry.json` → `npx shadcn add ./ultima-theme.registry.json` → "Import ultima-theme.css after your StyleX output. Set data-theme on your app root"), a font note ("your app supplies the font files"), a reinstall warning, and the three individual downloads `ultima-theme.json` / `ultima-theme.css` / `ultima-theme.stylex.ts` — all four artifacts, matching the contract verbatim; `RUDDo` is the invalid-draft acknowledgment: failing pairing listed, explicit checkbox "I understand this draft fails the listed contrast check.", "Back to editor" / "Export anyway". Not depicted (neither confirmed nor contradicted): share-link length fallback, corrupt-autosave quarantine, malformed-upload refusal, and the CLI overwrite prompt.

**"### Studio support components and compositions"** — confirmations: the Color Field anatomy (swatch trigger + hex input + popup) and its states (default, focused, invalid — "Enter a valid six-digit hex.", disabled) and SM/MD/LG sizes ("size is the only axis") all match the settled `color-field.tsx` contract; the token row composes color field + link toggle + reset as specified; the shuffle bar, group-header cluster, validation panel, inspector readout, and preview scaffold all appear as studio-local surfaces.

Divergence — the largest in the file: **`ColorField.Picker` is designed as a full custom picker, not the platform `input[type="color"]`.** Reusable components `T3fyKR` "Color Picker / dark" and `v7Cp7` "Color Picker / light" contain a 2D saturation/brightness area, a hue slider, an **alpha/opacity slider** ("Opacity 100%" on a transparency checkerboard), a format menu (HEX, RGB(A), HSL(A), HWB, OKLCH, OKLab, Lab, LCH, Display P3) with per-channel fields, and a gamut note ("Within sRGB gamut"). `eITqK` states it plainly: "PROPOSED CONTRACT: multi-format color with alpha. Preserve wide-gamut source values; generate fallbacks explicitly. Studio contrast checks must composite transparent colors against their actual backgrounds." The settled contract is opaque sRGB `#rrggbb` only, "no alpha, matching the override contract," with the platform picker in the popup — so this is an explicit counter-proposal for #234, which would also have to reconcile compositing transparent overrides against the "opaque only" validation model.
