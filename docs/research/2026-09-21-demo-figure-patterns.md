# How do Base UI, shadcn/ui, Radix Themes, Ark UI, and Mantine frame a live demo with its source?

## Findings

Four of the five put the preview and the code in one bordered frame with a separator between them; only Ark stacks two cards that share an edge. Three of the five hide most of the source at rest (shadcn shows a three-line teaser, Base UI about six lines, Ark nothing) and two show all of it (Radix Themes always, Mantine by default with a per-demo opt-out). All five put the copy control inside the code area, absolutely positioned at its top-right corner, as an icon-only button whose icon swaps to a check for one to two seconds. None put it in a footer row. Four of five center the preview on both axes; Radix lets content sit in normal flow. Min-heights run from none (Radix, Mantine) through 8rem (Base UI, Ark on phones) and 12rem (Ark) to a fixed 18rem (shadcn). At phone width nobody changes the figure's structure; the moves are hiding the copy button (Radix under 768px, Ark under 1024px), shrinking the preview's min-height and padding (Ark), and letting the toolbar and preview scroll horizontally (Base UI, Radix, Mantine).

Details per site follow, each read from the live page and the component that renders it. Sizes are the source values; rem conversions assume 16px.

### shadcn/ui

Page: <https://ui.shadcn.com/docs/components/button>. The MDX renders `<ComponentPreview styleName="base-nova" name="button-demo" />` (`apps/v4/content/docs/components/base/button.mdx`). The figure is `apps/v4/components/component-preview.tsx` delegating to `component-preview-tabs.tsx`, `component-source.tsx`, and `copy-button.tsx` in shadcn-ui/ui.

- Frame: one. `ComponentPreviewTabs` wraps preview and code in a single `div` with `relative mt-4 mb-12 flex flex-col overflow-hidden rounded-2xl border`. The code block inside loses its own top radius and gains a top border (`[&_[data-rehype-pretty-code-figure]]:rounded-t-none border-t`), so the separator is a line inside the frame. The code figure paints `background-color: var(--color-code)` with `border-width: 0px` (`apps/v4/app/globals.css`, `[data-rehype-pretty-code-figure]`).
- Source default: truncated teaser. `component-preview.tsx` passes two renders of `ComponentSource`: the full one and `sourcePreview` with `maxLines={3}`. Until the reader clicks, the tabs component shows the three-line teaser under an absolutely positioned overlay: a gradient from `var(--color-code)` up to transparent, and a centered outline `Button size="sm"` labelled `View Code`. Clicking sets `isMobileCodeVisible` and swaps in the full source; despite the state name there is no media query, this is the behaviour at every width. The expanded `pre` is capped at `[&_pre]:max-h-72` (18rem) and scrolls. There is no control to collapse again.
- Copy control: `CopyButton` is a `Button size="icon" variant="ghost"` with `absolute top-3 right-2 z-10 size-7 bg-code`, an `sr-only` "Copy" label and Tabler `IconCopy`. While the teaser is showing, the wrapper hides it (`**:data-[slot=copy-button]:hidden`); after `View Code` it becomes `flex` and sits at `right-4`. At rest it is fully opaque on the code background (the `hover:opacity-100` class is a no-op there). After a successful copy the icon becomes `IconCheck` for 2000 ms (`setTimeout` in `copy-button.tsx`). No tooltip, no text.
- Preview area: `PreviewWrapper` renders `preview relative flex h-72 w-full justify-center p-10` with `items-center` for `align="center"` and `items-start` for `start`/`end` (`end` becomes `items-end` at `sm` and up). That is a fixed 18rem height with 2.5rem padding, not a min-height. `chromeLessOnMobile` switches to `h-auto p-0`.
- Phone width: the figure is the same; the only responsive classes are `sm:data-[align=end]:items-end` and the `md:-mx-1` bleed. Copy stays hidden until `View Code`.
- Related: the standalone `ComponentSource` used elsewhere (with `collapsible`) uses `code-collapsible-wrapper.tsx`: closed state `max-h-64` (16rem) with an `Expand`/`Collapse` ghost button at top-right beside the copy button and a full-width gradient trigger (`h-20`, `from-code/70 to-code`) across the bottom that disappears when open.

### Base UI

Page: <https://base-ui.com/react/components/accordion>. Figure: `docs/src/components/Demo/Demo.tsx`, `DemoPlayground.tsx`, `DemoCodeBlock.tsx`, `Demo.css` in mui/base-ui, with `docs/src/components/GhostButton.tsx` and `.css`.

- Frame: one. `.DemoRoot` is `border: 1px solid var(--color-border); border-radius: var(--radius-12); margin-bottom: var(--space-24)`. Inside it, top to bottom: `.DemoPlayground` (background `--color-content`), a 2.25rem `.DemoToolbar` carrying the file tabs, the variant selector (CSS Modules / Tailwind), a StackBlitz (or CodeSandbox on WebKit) link and a "More actions" menu (View source on GitHub, Copy link to source), and `.DemoCodeBlockRoot` (background `--gray-s1`). The toolbar paints 1px separators above and below itself with a `::before` background.
- Source default: collapsed to about six lines when the file is long enough. `DemoCodeBlock` renders the file uncollapsed when `selectedFileLines < collapsibleLinesThreshold` (default 8); otherwise the viewport gets `data-closed` with `max-height: calc(5.7lh + 0.5rem)` and `overflow: hidden`, a `::before` gradient fades the bottom into `--gray-s1`, and a `Collapsible.Trigger.DemoCollapseButton` covers the whole closed block (`position: absolute; inset: 0`) so a click anywhere on the truncated code opens it; its visible pill (`.DemoCollapseButtonVisual`, 28px tall, `--radius-pill`) reads `Show code` and sits bottom-center 0.75rem above the border. Open, the pill reads `Hide code` and becomes `position: sticky; bottom: 0.75rem` with negative top margin so it floats over the code without adding a row. There is no max-height when open (a `clamp(8.75lh…)` rule is left commented out). On collapse, `onOpenChange` measures the pill before and after and scrolls the window by the delta so the button stays under the pointer.
- Copy control: a `GhostButton layout="icon"` (1.75rem square, `--radius-8`) with `aria-label="Copy code"`, `position: absolute; top: 0.5rem; right: 0.5rem; z-index: 3` inside the code block. It is always visible. Below `--md` (48rem) it gets a translucent backdrop `color-mix(in srgb, var(--gray-s1), transparent 10%)`; at md and up the backdrop is transparent. Hover under `(hover: hover)` paints `background-color: var(--gray-c1)`; focus-visible draws a 2px `--gray-t2` outline. After copying, `CopyIcon` becomes `CheckIcon` for 2000 ms.
- Preview area: `.DemoPlaygroundInner` (a `<figure aria-label="Component demo">`) has `padding: 2rem 1.5rem; min-height: 8rem; min-width: fit-content; display: flex; justify-content: center; align-items: center`. The outer `.DemoPlayground` is `overflow: auto hidden` so a wide demo scrolls horizontally instead of squashing. The code side is `<figure aria-label="Component demo code">`.
- Phone width: below `--sm` (40rem) the toolbar actions render inside the horizontally scrolling tab strip (`.DemoToolbarActionsMobile`, `margin-left: auto`); at sm and up a second, sticky copy of the actions outside the scroller takes over. Both copies stay mounted. The tab strip edge-fades with a mask driven by ScrollArea's overflow variables. The copy button keeps its backdrop below md because it can sit over code that scrolls beneath it.

### Radix Themes

Page: <https://www.radix-ui.com/themes/docs/components/button>. The MDX is a fenced block with `live=true` (`data/themes/docs/components/button.mdx`), rendered by the `pre` override in `components/mdx-components.tsx` of radix-ui/website, which composes `components/code-block.tsx` (`CodeBlock.Root`, `LivePreview`, `Content`, `Pre`, `CopyButton`) styled by `code-block.module.css`; the preview evaluates the code with `components/live-code.tsx`.

- Frame: one. `CodeBlock.Root` (`Box my="5"`) has `background-color: var(--code-block-background); border-radius: var(--radius-4)` and a 1px ring drawn with an `::after` `box-shadow: 0 0 0 1px var(--code-block-border)`. `LivePreview` sits on top with `background-color: var(--color-background)` and a `box-shadow: inset 0 -1px var(--code-block-border)` separator; `Content` with the `pre` and the copy button sits below. The variables come from `pages/syntax-highlighting.css` per accent colour (for example `--code-block-background: var(--color-panel-solid); --code-block-border: var(--gray-a5)`).
- Source default: open, always. There is no collapse, no teaser, and no max-height. `Pre` is `overflow: hidden; height: 100%; padding: var(--space-3) var(--space-4); line-height: 22px` wrapped in a Themes `ScrollArea`.
- Copy control: `IconButton color="gray" variant="soft"` with `aria-label="Copy code to clipboard"`, `position: absolute; top: 7px; right: 7px`. At rest it is invisible (`opacity: 0`, `transition: opacity 80ms ease-out`). It appears on `.CodeBlockContent:hover` under `(hover: hover)` and on its own `:focus-visible`. After copying (it reads `textContent` of the nearest `code`) `CopyIcon` becomes `CheckIcon` for 1500 ms.
- Preview area: `.CodeBlockLivePreviewInner` has `padding: var(--space-4)` (16px) and `line-height: 1`, with `text-wrap: pretty` on the container. No min-height and no centering: the rendered element sits top-left in normal flow. With the `scroll` meta the inner is `width: max-content` inside the ScrollArea.
- Phone width: `@media (max-width: 767px)` sets the copy button to `display: none`. The frame and open code are otherwise unchanged; wide previews scroll horizontally.

### Ark UI

Page: <https://ark-ui.com/docs/components/accordion>. The hero uses `<ComponentPreview id="Accordion" />` (preview only) and each example uses `<Example id="…" />` (`website/src/content/pages/components/accordion.mdx`). Files in chakra-ui/ark `website/src/components/`: `example.tsx`, `example-preview.tsx`, `collapsible-code.tsx`, `example-code.tsx`, `code-preview.tsx`, `code-block.tsx`, `copy-to-clipboard-button.tsx`, `component-preview.tsx`.

- Frame: two, glued. `Example` renders a `Stack gap="0"` whose first child, `ExamplePreview`, is a light `Flex` with `borderWidth="1px" borderRadius="lg" bg="bg.default"` and its bottom radius zeroed; below it `CollapsibleCode` renders either a closed trigger or a dark code card. The code card is a `Tabs.Root` with `bg="gray.dark.2" borderColor="gray.dark.5" borderRadius="lg"` (reset to 0 while inside the collapsible) and `className="dark"`, so the preview is in the page theme and the code is always dark. Nothing wraps both in a single border.
- Source default: collapsed, `lazyMount unmountOnExit`. Closed, the only thing under the preview is a full-width outline `Button size="xs"` reading `Show Code` with a Lucide `CodeIcon`, `borderTopRadius: 0; borderTopWidth: 0` so it hangs off the preview card. Open, the tab strip (`index.tsx`, sibling files, CSS module files, a `CSS` switch, a Stackblitz button) sits above the code, and a full-width `Hide Code` bar is `position: sticky; bottom: -1px` at the foot of the card. The code region is `maxH="xl"` (36rem) with `overflow: auto`.
- Copy control: `IconButton variant="ghost" size="sm"` with `aria-label="Copy code to clipboard"`, in a `position: absolute; top: 2; right: 3` (0.5rem / 0.75rem) box inside `CodePreview`. `display: none` below `lg` (64rem); at lg and up it is always visible, `_hover` paints `gray.dark.a3`. After copying, `CopyIcon` becomes `CheckIcon` for 1000 ms.
- Preview area: `minH={{ base: '32', md: '48' }}` (8rem, then 12rem from `md`); the inner `Flex` is `justify="center" align="center" direction="column" flex="1" p={{ base: '4', md: '6' }}` (1rem, then 1.5rem). The hero `ComponentPreview` uses `minH="40"` (10rem), `my="12"`, the same centering and padding, and `overflow="hidden"` except for the navigation menu, which gets `visible`.
- Phone width: min-height drops to 8rem and padding to 1rem; the copy button is gone below 64rem; the Stackblitz label hides below `sm` leaving the icon; the tab list scrolls horizontally with a right-edge mask so a clipped file name reads as overflow.

### Mantine

Page: <https://mantine.dev/core/button/>. The MDX renders `<Demo data={ButtonDemos.configurator} />` and `<Demo data={ButtonDemos.fullWidth} />` etc. (`apps/mantine.dev/src/pages/core/button.mdx`), with `Demo` from `@mantinex/demo` registered in `apps/mantine.dev/src/components/MdxProvider/MdxProvider.tsx`. Package sources in mantinedev/mantine: `packages/@mantinex/demo/src/{Demo,CodeDemo,ConfiguratorDemo,DemoRoot,DemoArea,DemoColumns,DemoCode}/`, and the code block from `packages/@mantine/code-highlight/src/{CodeHighlightTabs/CodeHighlightTabs.tsx,CodeHighlight/CodeHighlight.tsx,CodeHighlight.module.css}`.

- Frame: one. `DemoRoot` is `border: 1px solid var(--demo-border); border-radius: var(--mantine-radius-md)` (`gray-2` light, `dark-5` dark). `DemoArea` on top takes the inner top radii; `DemoCode` below has `border-top: 1px solid var(--demo-border)`, the inner bottom radii, and `overflow: hidden`. The configurator variant puts a 250px controls column to the right of the preview, which stacks under it at a container width of 620px or less (`DemoColumns.module.css`).
- Source default: open. `DemoCode` defaults `defaultExpanded = true` and `CodeHighlight` resolves `finalValue: true`. A demo can opt out with `defaultExpanded: false` in its data (for example `packages/@docs/demos/src/demos/core/Radio/Radio.demo.card.tsx`), which collapses the scroll area to `max-height: var(--ch-max-height, 180px)` with an 80px gradient `::after` and a full-width, centered, anchor-coloured text button `Expand code` at the bottom (`.showCodeButton`). `DemoCode` also passes `withExpandButton`, so an expand/collapse icon control with the tooltip `Expand code` / `Collapse code` sits in the top-right controls group. Fetched at `https://mantine.dev/core/button/`, the server-rendered HTML contains no `data-collapsed` attribute and 19 controls labelled `Collapse code`, so every demo on that page is open at load. Nothing caps the height when open.
- Copy control: the `.controls` group is `position: absolute; top: 8px; right: 8px` (12px when the file-tabs offset applies) and paints `background-color: var(--ch-background)` so it masks code beneath it. Inside, `CopyCodeButton` is an `ActionIcon variant="none"` with an 18px icon, `aria-label="Copy code"`, and a bottom-positioned Tooltip reading `Copy` then `Copied` (via `useClipboard`); the icon has a `copied` variant. At rest each `.control` is `opacity: 0.5`; hover raises it to `1` and brightens the colour. When file tabs are shown the `pre` gets `padding-top: 50px` and the tab row reserves `right: 70px` for the controls.
- Preview area: `DemoArea` has `padding: var(--mantine-spacing-md)` (1rem) when `withPadding` (default true), and `centered` switches it to `display: flex; justify-content: center; align-items: center`. `minHeight` and `maxWidth` are per-demo values written to `--demo-min-height` and `--demo-max-width` on the inner element; there is no global min-height. `dimmed` and `striped` backgrounds are available.
- Phone width: the demo CSS has no viewport queries; the configurator uses the container query above, the file-tab row is a `ScrollArea type="never"` that scrolls horizontally, and the copy control stays visible at 0.5 opacity because the hover rule is not gated on `(hover: hover)`.

### Comparison

| Site | Source default | Copy control placement | Frames | Preview min-height / alignment | Phone behaviour |
| --- | --- | --- | --- | --- | --- |
| shadcn/ui | Three-line teaser under a gradient with a `View Code` button; full source capped at 18rem, no re-collapse | Absolute top-right of the code (`top-3 right-2`, 1.75rem ghost icon); hidden until `View Code`; check icon 2s | One frame, top border between preview and code | Fixed 18rem, 2.5rem padding, centered both axes (`align` prop) | Same figure; no width-specific change |
| Base UI | Collapsed to about six lines when 8+ lines, `Show code` pill bottom-center over a fade; `Hide code` pill sticky when open; no cap when open | Absolute top-right of the code (0.5rem inset, 1.75rem ghost icon); always visible; translucent backdrop below 48rem; check icon 2s | One frame, toolbar separators between | 8rem, 2rem/1.5rem padding, centered both axes, horizontal scroll for wide content | Toolbar actions move into the scrolling tab strip below 40rem |
| Radix Themes | Open, always; no cap | Absolute top-right of the code (7px inset, soft IconButton); opacity 0 until content hover or focus; check icon 1.5s | One frame, inset 1px separator | None; 16px padding; top-left in flow | Copy button `display: none` below 768px |
| Ark UI | Collapsed and unmounted; full-width `Show Code` bar under the preview; sticky `Hide Code` bar when open; open code capped at 36rem | Absolute top-right of the code (0.5rem/0.75rem inset, ghost IconButton); always visible at 64rem and up; check icon 1s | Two stacked frames sharing an edge (light preview, dark code) | 8rem then 12rem from `md`; 1rem then 1.5rem padding; centered both axes | Copy hidden below 64rem; min-height and padding shrink; Stackblitz label drops |
| Mantine | Open by default; per-demo `defaultExpanded: false` collapses to 180px with `Expand code` text button; no cap when open | Absolute top-right of the code (8px inset) in a controls group with a code-coloured backdrop; 0.5 opacity at rest, 1 on hover; tooltip `Copy` then `Copied` | One frame, top border between | None by default (per-demo `minHeight`); 1rem padding; centered when `centered` | No viewport rules; configurator stacks at container 620px |

**What the majority does.** One outer frame holds both halves, preview above code, with a 1px line between them rather than a second border (shadcn, Base UI, Radix, Mantine). The preview is centered on both axes inside 1rem to 2.5rem of padding and given a floor of roughly 8rem (or nothing) rather than a fixed height; only shadcn fixes it at 18rem. Most of the source is hidden at rest and revealed by a control centered at the bottom edge of the code (shadcn, Base UI, Ark, and Mantine's opt-in all use that position), and once open the code is either capped and scrolling (shadcn 18rem, Ark 36rem) or uncapped (Base UI, Mantine, Radix). The copy control is an icon-only button about 1.75rem square, absolutely positioned inside the top-right corner of the code area on all five sites, and confirms by swapping to a check icon for one to two seconds; only Mantine adds a tooltip label. Whether it shows at rest splits three ways: always (Base UI, Ark, shadcn once open), on hover or focus (Radix), or dimmed to half opacity (Mantine). At phone width the structure never changes; the recurring adjustments are dropping the copy button (Radix, Ark), keeping a backdrop behind it when it sits over scrollable code (Base UI), and letting the toolbar or preview scroll horizontally rather than shrink.

### What translates to a Card-based figure with a separate highlighted code block

Ultima's `apps/docs/src/demo.tsx` renders `Card.Root` as a `figure` with three children: a preview `Card.Body`, a `Card.Body` holding `HighlightedCode`, and a `Card.Footer` holding `CopyButton` aligned to the end. Against the five sites:

- One Card as the single frame matches the majority; a visible separator between the preview body and the code body is what the four one-frame sites draw (a 1px line, not a second border). Base UI's `.DemoRoot` and Mantine's `DemoRoot` are the closest analogues to a Card with two bodies.
- A copy control in a footer row below the code has no precedent among the five; every site overlays it in the code's top-right corner. In a no-`className` codebase that means the code block's container takes `position: relative` through its `style` slot and the button is absolutely positioned inside it (shadcn's `ComponentCode` wraps the `figure` as `relative` with the button `absolute top-3 right-2`; Base UI's `.DemoCodeBlockCopyButton` does the same at 0.5rem). Sizes converge on 1.75rem square with a 0.5rem inset.
- If the button overlays scrolling code, give it a backdrop in the code's background colour (Base UI below 48rem, Mantine's `.controls`, shadcn's `bg-code`) so text does not run under it.
- The copied state is an icon swap to a check for 1500 to 2000 ms; only Mantine changes visible text, and it does so in a tooltip. An `aria-live` announcement is not part of any of the five copy buttons (Base UI uses one only for its "Copy link to source" menu item).
- For source visibility the split is a policy choice rather than a convention: teaser (shadcn 3 lines, Base UI about 6 lines) or fully hidden (Ark) versus open (Radix, Mantine). Every collapsed variant places the reveal control centered on the bottom edge of the code region over a gradient into the code background, and Base UI makes the whole truncated block clickable. Base UI's line threshold (do not collapse files under 8 lines) avoids a `Show code` button on a two-line demo. Mantine's 180px and shadcn's 16rem/18rem are the cap sizes in use.
- Preview: `min-height` of 8rem with flex centering is the common floor (Base UI, Ark phone); shadcn's fixed 18rem is the outlier. Padding runs 1rem to 2.5rem; Base UI's `min-width: fit-content` inside an `overflow-x: auto` container is the approach that keeps a wide demo intact on a phone, which fits the repo's settled bounded-scroll policy for docs regions.
- At phone width, keep the figure's structure and pick from: hiding the copy button (Radix, Ark), keeping it with a backdrop (Base UI), or leaving it (shadcn, Mantine). Ark's and Base UI's toolbars show that any tab or action strip above the code should scroll horizontally with an edge fade rather than wrap.
