# Sidebar

Application navigation as ten plain parts: a `Root` that holds the state, a `Panel` that is the `nav` landmark and the scroll container, and the groups, lists, links, and buttons inside it. Ultima paints the panel and the rows; routing stays yours, because `Sidebar.Link` takes your router's link through `render`.

Above `48rem` the panel sits inline and collapses in place. Below it, the same children become a menu that slides in over the page. You write them once.

The menu beside this page is this component, and it is the whole-navigation example: its groups, its nested set of component pages, its current row, the collapse control in the header, and the menu you get at a narrow width are all the parts below, wired to the site's router. The demos on this page each show one narrower thing.

## Install

```bash
npx shadcn add @ultima/sidebar
```

Installing Sidebar installs Dialog with it. `Sidebar.Root` composes `Dialog.Root` for the mobile menu, so the registry derives the dependency rather than asking you to remember it.

## The parts

`Root` sets no layout: the page decides where the panel and the content sit. `Group` spaces a section, `GroupLabel` is a real `h3`, `List` is a reset `ul`, and `Item` is a bare `li`. `Link` and `Button` share one row style, so a destination and an in-place action look alike.

`Trigger` and `Close` are the two controls. Both are wrapper triggers: they ship no styles at all, so the slot holds an Ultima Button or an element carrying its own focus ring. `Close` renders nothing above the breakpoint, where there is no menu to close, so it costs you no condition of your own.

## The current page

`Sidebar.Link` takes `active`, and Base UI emits `aria-current="page"` and `data-active` when it is true. The current row differs from a resting one by fill, by weight, and by an inline-start bar, so it never depends on hue alone.

The style reads `aria-current` as well as `data-active`, which means a router link that sets the attribute itself, as TanStack Router's does, is styled with no `active` prop at all.

## A nested group

There is no `SubList` part. A nested group is `Collapsible.Root` around an `Item`, `Collapsible.Trigger render={<Sidebar.Button />}`, and a nested `Sidebar.List` inside `Collapsible.Panel`. Each `List` reads how deep it sits and indents itself, so the levels compound with no prop.

## Collapsing the panel

`Sidebar.Trigger` toggles the desktop collapse and carries `aria-expanded` and `aria-controls` for the panel. The panel animates its inline size to zero over `--ult-motion-base`, so content beside it reflows rather than a box vanishing. Width is an ordinary property: change it through the `style` slot on `Panel`.

<Demo component={Collapse} source={collapseSource} />

## A scrolling panel

`Panel` is the scroll container. It sets no block size, so it is content-sized inside a page that gives it one; set a height through the `style` slot when you want the navigation to scroll on its own. The bar follows `--sidebar-scrollbar-width`, which defaults to `auto`: set it to `none` or `thin` on the panel to restyle it.

## Below the breakpoint

The breakpoint is `48rem`, and it is not configurable. Two halves read the same string: a media query decides what is visible, and a `matchMedia` subscription decides what mounts. A prop could move the mount but not the media query, which is a runtime value in a place CSS will not take one, so the two halves would disagree. Changing the breakpoint means editing the copy of `sidebar.tsx` you own.

Below it, `Panel` puts its children inside Ultima's Dialog: a backdrop, a popup anchored to the inline start, and the same `nav` inside it. `Trigger` becomes the dialog's trigger and `Close` becomes its close, so focus entry, the focus trap, Escape, the backdrop, the scroll lock, and the return of focus to the trigger are Dialog's and not reimplemented. The popup reuses the name you gave `Panel` and renders no heading of its own. Sidebar adds exactly one behavior on top: choosing a link closes the menu.

The server render is the desktop shape, which is the crawlable one, and the media query keeps it out of sight on a narrow viewport until the mobile branch mounts.

**A desktop reader cannot be shown the menu on this page, by any construction**, so this page does not try. There is no iframe and no second demo composing Dialog by hand, which would copy this file's private overrides and then drift from them. Narrow your window instead: the site's own menu and every demo above carry a `Sidebar.Trigger`, so each one becomes the real menu at a real width rather than a picture of it.

## The state, and useSidebar

`Root` holds two states, because a desktop collapse is a preference and a mobile menu is a transient overlay. `open` persists what you chose; `mobileOpen` is the menu, and it defaults closed. `toggle` flips whichever one applies at the current width, which is what `Trigger` calls. Crossing the breakpoint upward closes the menu and leaves your desktop preference untouched. Both follow the controlled-or-uncontrolled pattern, resolved per render, so you can move between the two.

`useSidebar()` is exported beside `Sidebar` and returns `{ open, setOpen, mobileOpen, setMobileOpen, isMobile, toggle }`. It is how you build a part of your own — a keyboard shortcut, a persisted preference — that reads or sets the same state. It throws `useSidebar must be used inside Sidebar.Root` when called outside the root, because a silent no-op would hide your bug.

## Props

Sidebar has no axis. Every part takes `render` and the `style` slot.

| Part | Prop | Type | Default | Notes |
| --- | --- | --- | --- | --- |
| `Root` | `open`, `defaultOpen`, `onOpenChange` | `boolean`, `boolean`, `(open: boolean) => void` | `defaultOpen` is `true` | The desktop collapse. |
| `Root` | `mobileOpen`, `defaultMobileOpen`, `onMobileOpenChange` | `boolean`, `boolean`, `(open: boolean) => void` | `defaultMobileOpen` is `false` | The mobile menu, below `48rem`. |
| `Close` | — | — | — | Renders `null` above the breakpoint. |
| `Panel` | `aria-label` or `aria-labelledby` | `string` | — | Required, as a union. The type rejects an unnamed panel. |
| `Panel` | `container` | `Dialog.Portal`'s `container` | `<body>` | Where the mobile menu portals below the breakpoint, such as inside a scoped theme. |
| `Link` | `active` | `boolean` | `false` | Emits `aria-current="page"` and `data-active`. |
| every part | `render` | `ReactElement \| function` | — | Base UI's render prop, through `useRender`. |
| every part | `style` | `StyleXStyles` | — | The style slot, merged last. There is no `className`. |

`Panel` carries `data-open` or `data-closed` from the root's state, so a style of yours can follow the collapse. Those are the desktop collapse, so a style reading them nests the condition inside the same media query Sidebar does; below the breakpoint the menu is either mounted or it is not.

## Accessibility

- **Name.** `aria-label` or `aria-labelledby` on `Sidebar.Panel`, which the type requires: a page with a sidebar has at least two navigation landmarks, and an unnamed one fails the unique-label rule. The mobile popup takes that same name, which is why it is the one Ultima dialog with no `Dialog.Title`. The elements rendered into `Trigger` and `Close` carry their own `aria-label` when they are icon-only.
- **Focus ring.** On `Link` and `Button`. `Trigger` and `Close` are wrapper triggers and ship no styles at all, so the slot must hold an Ultima Button or an element carrying its own ring.
- **Keyboard.** Native. `Link` is an `a`, `Button` is a `button`, and Tab, Enter, and Space are the browser's. Group disclosure is Collapsible's, and the mobile menu is Dialog's: Tab loops inside it, Escape closes it, and focus returns to the trigger. Navigation is a list with disclosure buttons, never `role="tree"` or `role="menu"`.
- **Elements.** `nav` on `Panel`, `ul` and `li` on `List` and `Item`, `h3` on `GroupLabel`, changeable through `render` like `Card.Title`.

Three obligations are the consumer's, not Sidebar's: one link current per set, a name on the panel, and moving focus to the new page's heading on a client-side route change. This site meets all three in `apps/docs`: its links are TanStack Router links passed through `render`, which set `aria-current` themselves and match exactly so only one row is current; the panel is named `Ultima`; and the shell moves focus to the destination's `h1` once the route resolves.
