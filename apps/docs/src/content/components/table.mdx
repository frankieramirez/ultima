# Table

A data table built from native table parts, with an optional caption, an optional scroll region, and a sortable column header.

## Install

```bash
npx shadcn add @ultima/table
```

## Anatomy

`Root` is the `table`. `Head`, `Body`, `Row`, `HeadCell`, and `Cell` are the `thead`, `tbody`, `tr`, `th`, and `td` inside it. `Caption` names the table, and `Scroll` is the optional region around it.

`HeadCell` also takes a `sort`, and `SortButton` is the control that sits inside it. Those two arrived in v0.2 for the Data Table recipe; the other eight parts are v0.

## Horizontal scrolling

Wrap a table wider than its column in `Table.Scroll`. The region joins the tab order while the table overflows and drops out of it when the table fits, so a keyboard user reaches the overflow and scrolls it with the arrow keys without meeting a dead stop on a table that needs none.

A `Table.Caption` is required whenever `Table.Scroll` is used, because the caption is what names the region through `aria-labelledby`. An uncaptioned table that scrolls belongs in a Scroll Area instead: its viewport is presentational, so it delivers the same tab stop without adding an unnamed landmark. The minimum width goes through the `style` slot on `Table.Root`.

<Demo component={HorizontalScroll} source={horizontalScrollSource} />

## Sortable columns

Give a `Table.HeadCell` a `sort` of `ascending`, `descending`, or `none` and it emits both `aria-sort`, which a screen reader announces, and `data-sort`, which your CSS can read. A head cell with no `sort` emits neither, so only the columns a reader can actually sort advertise one.

`Table.SortButton` is the control inside the cell, and it ships no styles at all: hand it your own button through `render`, the way you would `Dialog.Trigger`. `render={<Button variant="ghost" />}` is the canonical fill, and the focus ring a keyboard user sees is that Button's. The glyph is yours too. The demo's caret turns on `data-sort` and takes its value from the same place the cell does, so the arrow and the announcement cannot disagree.

Sorting the rows is not Ultima's. Both parts are presentational: the cell announces the state you hand it and the button is a slot. The Data Table recipe is where the row model lives.

## Data Table

Data Table is a recipe, not a component: there is nothing to install from Ultima beyond the parts above. The row model is [TanStack Table](https://tanstack.com/table) v9, and it is your dependency.

```bash
npm install @tanstack/react-table
```

That package is ESM-only and declares `engines.node >= 20`, so a toolchain that `require()`s it cannot load it. The [long form is on the install page](/install#steps-you-still-do-by-hand). No file in `@ultima/ui` imports the engine, so no registry item declares it and nothing arrives with `@ultima/table`.

Component dependencies: `table`, `button`, `checkbox`, `dropdown-menu`, `input`, `select`, `pagination`.

Register features per example. v9 computes the table's type from `tableFeatures()`, so the APIs of a feature you did not register do not exist — sorting registers `rowSortingFeature`, its row model, and the sorting functions its columns use, and nothing else. Read the engine's sort state onto the cell with `sort` and put the control inside it with `SortButton`; the arrow direction a number column opens with is the engine's default, not Ultima's.

The announcement is the third obligation, and it is yours. A sort moves rows silently: the `aria-sort` change speaks only while focus is on the button that changed it. Mount a `role="status" aria-atomic="true"` region empty, clip-hide it rather than setting `display: none`, and write the new order into it. Two columns can land the same rows in the same order, and identical consecutive text is not a change, so a repeat appends a Word Joiner. The text is application-specific, which is why no part and no shared announcer ships it.

### Row selection

Row selection is a second `tableFeatures()` call, not an addition to the one above: registering `rowSelectionFeature` here leaves the sorting example's table without it, which is the whole point of registering per example. The engine supplies the selection model and nothing else. Every checkbox on the page is Ultima's `Checkbox`, because where a recipe hands you a control that control comes from the catalogue, and the roles, the ARIA state, the keyboard, and the focus ring are its.

The select-all is a standalone `Checkbox.Root` with a controlled `indeterminate`, not a `Checkbox.Group` parent. The header checkbox and the body rows are not one group: the rows live in the `tbody` and the parent lives in a `th`. `parent` plus `allValues` on `Checkbox.Group` is the form-list recipe for a select-all that *is* in the same group, and reaching for it here would put a `role="group"` around a table. Base UI turns `indeterminate` into `aria-checked="mixed"`, and the dash glyph is the visible signal.

Three obligations are the consumer's, not the recipe's. Each row checkbox takes its name from that row's own data, because four checkboxes all reading "Select row" identify no row. The select-all takes its own distinct name. And the change is announced: the same `role="status"` region the sorting example introduced, carrying the selection count rather than the row order. One region for the table; a second would say the same thing twice.

<Demo component={DataTableRowSelection} source={dataTableRowSelectionSource} />

### Filtering

Filtering registers `columnFilteringFeature`, `columnFacetingFeature`, the filtered and faceting row models, and the `filterFns` map its columns name. The demo shows two surfaces sharing that one registration. The faceted menu is a `DropdownMenu` of `CheckboxItem`s fed by `column.getFacetedUniqueValues()`, so each option carries its count, and its trigger is a `Button` through `render`. Checking a value sets the column's filter to the checked list under `arrHas`, which keeps a row whose value is one of the checked; `closeOnClick={false}` keeps the menu open while you check more than one. The global search is an `Input` named with `aria-label` driving `table.setGlobalFilter`, which is `globalFilteringFeature`: it cannot run without column filtering, which is why it shares this demo rather than earning one of its own.

The announcement obligation is the same `role="status"` region again, this time carrying the visible count against the total.

<Demo component={DataTableFiltering} source={dataTableFilteringSource} />

### Pagination

Pagination registers `rowPaginationFeature` and `createPaginatedRowModel()` with controlled `{ pageIndex, pageSize }` state: the demo holds it in `useState` and hands the slice back through `state` and `onPaginationChange`. Page navigation is the catalogue `Pagination`, mounted above and below the table. Two of one landmark on a page need distinct names, so each takes an `aria-label`. The page-size control is a `Select` writing `table.setPageSize`, which keeps the top row in view rather than stranding you on a page that no longer exists.

The `role="status"` region here announces the visible range, because Pagination mounts no live region of its own: it sees pages and never items, so the item range is the recipe's to say. When you combine these examples on one table, register every feature on that table and the pipeline orders them core, then filtering, then sorting, then pagination; `autoResetPageIndex` keeps a filter change from stranding the reader on an empty page.

## Chart

A chart is a recipe, not a component: there is no `@ultima/chart` item and no file to install. The engine is the pure-function [d3](https://d3js.org/) modules, and they are your dependency — `d3-scale`, `d3-array`, and `d3-format` cover the example below, while a line or arc mark pulls in `d3-shape` and `d3-time-format`.

```bash
npm install d3-scale d3-array d3-format
```

No file in `@ultima/ui` imports the engine, so no registry item declares it and nothing arrives with `@ultima/table`. `d3-axis` is not on the list: it renders DOM, which fails the recipe engine gate, so axes and ticks are markup you write yourself, read off `ticks()` and `tickFormat()` on the scale objects. The scales compute positions and bands, `max` and `extent` bound the domain, and `tickFormat` prints the labels.

Component dependency: `table`.

**The SVG is decoration and the Table is the data.** The chart renders `aria-hidden="true"` and the same rows sit in a real `Table` beside it, which is why `table` is the recipe's only component dependency and why the recipe lives on this page. Naming the SVG with `role="img"` instead is declined: with the data table present, a name announces the same information twice, and a chart shipped without its table is an inaccessible example.

The canonical example is a single-series bar chart: `scaleBand` for the categories, `scaleLinear` for the values, marks in `--ult-color-accent`. Line, arc, and multi-series marks follow the same rules.

## Props

Only what Ultima adds. The parts otherwise accept the corresponding [native table element props](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/table).

| Part | Prop | Type | Default | Notes |
| --- | --- | --- | --- | --- |
| Every part | `style` | `StyleXStyles` | — | The style slot, merged last. There is no `className`. |
| `Root` | `render` | `ReactElement \| function` | — | Changes the root from its default `table`. |
| `Scroll` | `aria-labelledby` | `string` | — | The `Table.Caption` id, which names the region. |
| `HeadCell` | `scope` | `'col' \| 'row' \| 'colgroup' \| 'rowgroup'` | `'col'` | Override with `row` for row headers. |
| `HeadCell` | `sort` | `'ascending' \| 'descending' \| 'none'` | — | v0.2. Emits `aria-sort` and `data-sort`; omitted, it emits neither. |
| `HeadCell` | `render` | `ReactElement \| function` | — | Changes the cell from its default `th`. |
| `SortButton` | `render` | `ReactElement \| function` | — | v0.2. The slot for your own button. Unstyled, so what you render carries the reset and the ring. |

## Accessibility

- **Elements.** Native `table`, `thead`, `tbody`, `tr`, `th`, `td`, and `caption` parts, plus `Table.Scroll` as a `div` with `role="region"`.
- **Name.** `Table.Caption` is optional on a bare table and required under `Table.Scroll`, which it names through `aria-labelledby`.
- **Headers.** `Table.HeadCell` defaults to `scope="col"`; override it for a row header. Its `sort` emits `aria-sort` on the same `th`, which is where a screen reader looks for it.
- **Focus and keyboard.** The table itself is static. `Table.Scroll` is the only part that enters the tab order, and only while its content overflows; it takes the focus ring. Without it nothing inside a table is focusable. `Table.SortButton` is a wrapper trigger, so the element you render into it must carry its own focus ring: an Ultima `Button` does.
