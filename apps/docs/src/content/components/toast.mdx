# Toast

A stacked notification built on Base UI's Toast. It is not an overlay: it sits above the popup layer on its own `z.toast`, and it keeps its own enter and exit rather than the shared popup transition.

## Install

```bash
npx shadcn@4.21.4 add @ultima/toast
```

## Stacked

Mount `Toast.Provider`, `Toast.Portal`, and `Toast.Viewport` once in your tree. Portal and Viewport stay mounted when the stack is empty, and that is deliberate: the Viewport *is* the live region, and a region inserted at the same moment its text arrives announces nothing. Queue a toast from anywhere under the Provider with `Toast.useToastManager()`.

<Demo component={Stacked} source={stackedSource} />

The stack collapses to the frontmost toast's height and expands on hover or focus. `Toast.Action` and `Toast.Close` are unstyled slots for a control with its own focus ring. The canonical Action is a solid Button, `render={<Button size="sm" />}`: it is the one thing the toast offers, and it has seconds to be found, so it takes a fill where a ghost Button would read as text. Close stays quiet, `render={<Button variant="ghost" size="sm" />}`. Keep Button's own `tone`: the action's color says what pressing it does, so a Retry on an error toast is not a danger Button. Swipe-to-dismiss is Base UI's, along with `limit`, `timeout`, `swipeDirection`, and `priority`, which pass through and are not axes.

## Tone

`tone` is not a prop on `Toast.Root`. Pass Base UI's `type` to `add()` or `promise()` and Ultima styles `[data-type]`, so a caller never names a token:

```tsx
toasts.add({ title: 'Report exported', type: 'success' });
```

The six values are Badge's: `neutral`, `accent`, `highlight`, `success`, `warning`, `danger`. A toast added with no `type` paints `neutral`. Two more strings are aliases rather than extra values, so `promise()` works without a wrapper: `error` paints as `danger`, and `loading` paints as `neutral`.

Colour never carries meaning alone. The Title, or the Description when there is no Title, is the signal, and `Toast.Icon` repeats it as a mark.

## Status icon

Put `Toast.Icon` first in `Toast.Content`. It reads the toast's `type` from the Root, so it takes no prop, and draws the mark for a status in the tone's ink: a circled check for `success`, a triangle for `warning`, a circled exclamation for `danger` and `error`, and a turning ring for `loading`, so a `promise()` toast keeps its mark's place when it settles. `neutral`, `accent` and `highlight` report no status, so the Icon renders nothing there and the text keeps the start edge. Children replace the mark, on any type, with an icon from your own set in `Icon`. The glyphs are drawn inline, so Toast carries no icon dependency.

## Queueing from outside React

`Toast.createToastManager()` builds a manager you can hold outside the tree and hand to the Provider. It exposes the same `add`, `close`, `update`, and `promise` as the hook, without the reactive `toasts` array:

```tsx
export const toasts = Toast.createToastManager();

<Toast.Provider toastManager={toasts}>{/* ... */}</Toast.Provider>;
```

Both sit on the `Toast` namespace as values. Ultima ships no `useToast()` and does not wrap `add()`.

## The live-region pattern

Ultima owns a documented pattern here rather than a component. There is no announcer to install, and `Toast.Viewport` is the only live region Ultima's own UI gets for free.

- **The region is in the tree before the text changes.** Core-AAM only maps changes *inside* a live region; inserting the region itself is silent. Mount it empty, and never hide it with `display: none`, `hidden`, `aria-hidden`, or conditional rendering. Gating `Toast.Portal` on `toasts.length` defeats it.
- **Your own regions use `role="status"` with an explicit `aria-atomic="true"`.** `role="alert"` is for a form error or an equally imperative message. Identical consecutive text is not a change, so append Word Joiner (U+2060) when the same string is announced twice.
- **A visually hidden region is clip-hidden**, `clip-path: inset(50%)` inside a 1px box, not `display: none`.
- **Announcements are not assertable.** axe has no live-region rule, and its `region` rule skips `status`, `log`, and `alert` subtrees. There is no build step that can catch a missing region, which is why this is written down rather than enforced.

## Anchored toasts

`Toast.Positioner` and `Toast.Arrow` sit on the namespace for a toast anchored to an element, with `positionerProps` on the toast object. An anchored Root sizes to its message up to 320px, or the space available, and wraps past that.

Give each trigger one confirmation. Pass a fixed `id` per trigger, so pressing it again updates the toast already on screen and restarts its timer instead of stacking a second one at the same anchor:

```tsx
toasts.add({ id: 'copy-link', title: 'Link copied', type: 'success', positionerProps: { anchor: button } });
```

Toasts at different anchors stay apart, so an anchored toast keeps its text when a newer one opens elsewhere. Only the stacked deck hides the content behind its front toast.

## Props

Only what Ultima adds. Every inherited part and prop is documented by [Base UI's Toast](https://base-ui.com/react/components/toast).

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `style` | `StyleXStyles` | — | Available on the styled Viewport, Positioner, Root, Content, Icon, Title, Description, and Arrow parts; merged last. There is no `className`. |
| `render` | `ReactElement \| function` | — | Base UI's render prop. Action and Close are unstyled slots for a control with its own focus ring. |
| `children` on `Icon` | `ReactNode` | the status mark | Replaces the mark, shown on every type. |
| `type` | `'neutral' \| 'accent' \| 'highlight' \| 'success' \| 'warning' \| 'danger'` | `neutral` | Base UI's own option on `add()`, styled by Ultima through `data-type`. `error` and `loading` are aliases for `danger` and `neutral`. |

## Accessibility

- **Name.** `Toast.Viewport` is a `role="region"` labelled `Notifications`, with `aria-live="polite"`. Each `Toast.Root` is a `role="dialog"` named by `Toast.Title` and described by `Toast.Description`, with `aria-modal={false}`.
- **High priority.** `priority: 'high'` makes the Root a `role="alertdialog"` and announces it through Base UI's own visually hidden `role="alert"` clone of the title and description. The visible Root stays `aria-hidden` until the viewport is focused. Ultima does not restyle, wrap, or replace that clone.
- **Icon.** `Toast.Icon` is `aria-hidden`. The Title says the status in words.
- **Focus ring.** On the elements rendered into `Toast.Action` and `Toast.Close`. The slots ship no styles at all, so the ring is the Button's.
- **Keyboard.** Base UI owns it: <kbd>F6</kbd> jumps into the viewport, and a swipe past the threshold dismisses. Base UI keeps Close `aria-hidden` while the stack is collapsed and untouched, so a toast that is only an announcement reads as its title and description alone.
