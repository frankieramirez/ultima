# Install

Ultima ships as a shadcn-compatible registry. You copy source into your project with the CLI and own it after that.

<Callout icon={<InfoIcon />} title={<><Code>npx shadcn init</Code> is not supported.</>}>Its preflight requires Tailwind on disk, and Ultima does not use Tailwind. The entry is a per-target setup item, which is a universal `registry:item` and installs into a project that has no `components.json` yet.</Callout>

## Commands

<InstallCommands />

The first command writes `components.json` and the StyleX compiler config. It also writes the `@ultima` registry into that file, so the second command resolves through the namespace. You never run `shadcn registry add` by hand.

Add more components the same way: `npx shadcn add @ultima/card`. `registryDependencies` pulls the tokens and lib items in transitively.

## What the setup item installs

A setup item never overwrites a file your scaffold already owns.

**Both.** Each `components.json` sets the style to `base-ultima`, whose prefix enables Base UI's `render` transform. It leaves the Tailwind config empty and keeps Tailwind's CSS variables on, because turning them off enables a transform that rewrites string literals in installed source. The aliases are flat, for components and lib, and the file registers the `@ultima` namespace. React Server Components are on for Next and off for Vite.

**Why resets need a layer.** Every StyleX rule sits in a cascade layer, so an unlayered reset such as create-next-app's `* { padding: 0 }` beats component styles, including a Button's own padding.

```css title="src/index.css · app/globals.css"
@layer reset {
  *,
  *::before,
  *::after {
    box-sizing: border-box;
  }

  body {
    margin: 0;
  }
}
```

**Only if you follow the Data Table recipe.** `@tanstack/react-table` v9 is ESM-only. It ships no CJS and no UMD build and declares `engines.node >= 20`, so a toolchain that `require()`s it cannot load it: a CJS config path, or a test runner without ESM support. Nothing else Ultima documents asks this of you, and Ultima does not pin the last dual-published major to buy CJS back — it is more than a year old, and a toolchain that cannot resolve ESM cannot compile StyleX either.

## Tokens without StyleX

Components need a StyleX compiler. Tokens do not.

The stable URL is `https://ultima.systems/tokens.css`. Mana's audit report fetches or vendors that file and inlines it. The `tokens-css` registry item writes the same generated stylesheet to `~/ultima-tokens.css` if you want it committed next to your source.

The export is plain CSS, with no imports, no URL references, and no remote fonts. It follows the system color scheme on `:root` and also ships `[data-theme="dark"]` and `[data-theme="light"]` blocks, so an attribute on the root element pins a document to one mode.

## Web components

Nine components also ship as custom elements for a host that cannot run React, installed the same way as a registry item (`npx shadcn add @ultima/ult-button`) or loaded from `https://ultima.systems/elements/`. The [Elements](/elements) page has both paths and the styling story.

## For an agent

Install the `ultima-design` skill through skills.sh, the Ultima marketplace in Claude Code, or the consumer CLI. The [CLI page](/cli#other-skill-installers) lists the commands and explains which route also installs post-edit hooks. GitHub installation requires repository access until Ultima becomes public.

The skill directs your agent to [`/llms.txt`](/llms.txt) before UI work and to CLI checks after edits. The hosted guide contains the principles, conventions, component imports and props, and token names. It is generated on every build; the skill carries workflow instructions and links to that guidance.

## Theme adoption

[Theme Studio](/theme-studio) generates a theme for an existing Ultima application. Download the registry file, then run:

```sh title="Terminal"
npx shadcn add ./ultima-theme.registry.json
```

The registry installs `ultima-theme.css`, `ultima-theme.json`, and `DESIGN.md` at the project root. Keep the JSON draft for later editing. The design document describes the current draft for people and agents. Reinstalling replaces the generated files.

To start with Ultima's default design document on its own, run `npx shadcn add @ultima/design-md`. Review the file for your application and update it when you change the theme.

Import the stylesheet after your application's StyleX output. For Vite, in `src/main.tsx`:

```tsx title="src/main.tsx"
import './index.css';
import '../ultima-theme.css';
```

For Next.js, in `app/layout.tsx`:

```tsx title="app/layout.tsx"
import './ultima.css';
import '../ultima-theme.css';
```

For Next.js with `src/app/layout.tsx`:

```tsx title="src/app/layout.tsx"
import './ultima.css';
import '../../ultima-theme.css';
```

Set `data-theme="dark"` or `data-theme="light"` on `html` to select a mode. Remove the attribute to follow the system preference. The generated CSS sets `color-scheme` and respects reduced motion. It exports font stacks; load your preferred font faces yourself or use the fallbacks.

The optional StyleX export contains all token groups. Apply both `ultimaTheme.dark` and `colorScheme.dark` to a dark scope, or their light equivalents to a light scope. Put the portal containers for Select, Dialog, Popover and other popups inside that scope. A popup attached to `document.body` inherits the document theme instead.

Run `npx ultima-design doctor` and `npx ultima-design check`, then compare your production build with the Studio preview. Check the root, an Ultima control and an open popup in dark, light and system mode, including focus, disabled states and reduced motion. The commands cannot prove that the browser applied the stylesheet.
