# Install

Ultima ships as a shadcn-compatible registry. You copy source into your project with the CLI and own it after that.

`npx shadcn init` is not supported. Its preflight requires Tailwind on disk, and Ultima does not use Tailwind. The entry is a per-target setup item, which is a universal `registry:item` and installs into a project that has no `components.json` yet.

## Commands

Vite:

```bash
npx shadcn add https://ultima.systems/r/setup-vite.json
npx shadcn add @ultima/button
```

Next.js App Router:

```bash
npx shadcn add https://ultima.systems/r/setup-next.json
npx shadcn add @ultima/button
```

The first command writes `components.json` and the StyleX compiler config. It also writes the `@ultima` registry into that file, so the second command resolves through the namespace. You never run `shadcn registry add` by hand.

Add more components the same way: `npx shadcn add @ultima/card`. `registryDependencies` pulls `tokens` and `lib` transitively.

## What the setup item installs

A setup item never overwrites a file your scaffold already owns.

**Vite.** `components.json` and `ultima.vite.ts` at the project root. `ultima.vite.ts` exports `ultimaStylex()`, the StyleX unplugin with `useCSSLayers: true`, `runtimeInjection: false`, the `unstable_moduleResolution` root, and the `@/` alias. You add two lines to your own `vite.config.ts`: the import, and `ultimaStylex()` first in `plugins`. Shipping a `vite.config.ts` would destroy yours.

**Next.js App Router.** `components.json`, `babel.config.js`, `postcss.config.js`, and `app/ultima.css` (the `@stylex;` marker). None of those exist in a fresh App Router app, so nothing is clobbered. Turbopack finds the Babel config on its own.

Both `components.json` files set `style: "base-ultima"` (the `base-` prefix enables Base UI's `render` transform), an empty `tailwind.config`, `tailwind.cssVariables: true` (`false` turns on `transformCssVars`, which rewrites string literals in installed source), flat aliases (`@/components/ui`, `@/lib`), and `registries["@ultima"]`. `rsc` is `true` for Next and `false` for Vite.

## Steps you still do by hand

The `docs` field on each setup item prints a short list at install. This page is the long form.

**Vite.** Add `"paths": { "@/*": ["./src/*"] }` to `tsconfig.json` and `tsconfig.app.json`. Without it the CLI writes files into a literal `./@/` directory and reports success. Then add `ultimaStylex()` to `vite.config.ts`, before the React plugin.

**Next.js.** Import `./ultima.css` from `app/layout.tsx`.

**Both.** Wrap global resets in an `@layer`. Every StyleX rule sits in a cascade layer, so an unlayered reset such as create-next-app's `* { padding: 0 }` beats component styles, including a Button's own padding.

```css
@layer reset {
  *,
  *::before,
  *::after {
    box-sizing: border-box;
  }

  body {
    margin: 0;
  }
}
```

## Tokens without StyleX

Components need a StyleX compiler. Tokens do not.

The stable URL is `https://ultima.systems/tokens.css`. Mana's audit report fetches or vendors that file and inlines it. The `tokens-css` registry item writes the same generated stylesheet to `~/ultima-tokens.css` if you want it committed next to your source.

The export is plain CSS: no `@import`, no `url()`, no remote fonts. It follows `prefers-color-scheme` on `:root` and also ships `[data-theme="dark"]` and `[data-theme="light"]` blocks so you can pin a document to one mode with an attribute on `<html>`.

## For an agent

Point an agent at [`/llms.txt`](/llms.txt): the principles, the conventions, every component's import and props, and the token names, as plain Markdown at one URL. It is generated on every build, and it is the only guidance Ultima publishes for a consumer's repository — nothing documentary is installed into yours.
